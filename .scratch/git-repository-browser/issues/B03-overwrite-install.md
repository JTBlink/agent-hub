# 将已有 Skill 的仓库导入改为覆盖安装并提交

## Comments

- 用户明确要求详情中的操作为覆盖安装，并要求完成后创建本地提交。
- 修复前回归测试在详情中找不到「覆盖安装」按钮，已有行为只支持再次导入，不能表达覆盖指定库内记录。
- 显式传递目标 Skill ID，复用暂存、目录交换、来源记录更新及部署刷新逻辑；不使用删除数据库行后重新安装的方式，避免丢失标签、组与部署关系。
- 本地及远程仓库共用覆盖实现；只允许写入应用管理的技能库副本，拒绝外部原地登记目录、源与目标重叠、已删除目标，以及同一批次对同一目标选择多个版本。

## Result

- [详情及确认](../../../src/components/GitRepositorySkills.tsx) 改为「覆盖安装 → 确认覆盖安装」，列出已有目标并明确替换内容与来源；覆盖项的名称只读，确认前无写入。批量操作也绑定各自已有 Skill ID。
- [前端安装链路](../../../src/hooks/useGitRepositories.ts) 将明确的覆盖目标传给本地及远程 API，拒绝同批次重复目标；取消或失败保留可重试状态，安装结束重新读取库内状态。
- [覆盖实现](../../../src-tauri/src/commands/skills/repository_install.rs) 复用来源校验、RepoLock、暂存与目录交换、原记录更新及部署刷新。保留原有 ID、创建时间、启停状态、标签、组成员和部署关系，不生成后缀副本，并写回来源与同步元数据。既有不带覆盖字段的调用保持兼容。
- 4 项 Rust 回归覆盖本地/远程覆盖、身份与关联保留、复制部署刷新、失败保留旧内容、越界/重叠路径保护、重复目标及旧 DTO 兼容；前端补充目标传递、重复覆盖拦截与用户确认测试。
- `npm test`：88 个文件、496 项通过；`npm run lint`、`npm run build`、相关文件 Prettier、帮助文档校验、tracker 索引及 `git diff --check` 通过。构建保留既有 Browserslist 数据过期与大 chunk 提示。
- Rust 全量：库测试 715 项与 CLI 测试 8 项通过，8 项按既有设置忽略；`cargo fmt --check` 与严格 Clippy 通过。
- Standards：未通过删除数据库行实现覆盖，复用现有安全边界与暂存交换；暂存区隐私检查无个人绝对路径、账户字面量或非保留域邮箱。Spec：实际替换旧内容、保留关联并更新来源，确认前不写入，相关本地/远程链路和显示状态均有测试。
- 已更新三语文案、帮助、目录结构、CHANGELOG 与任务记录；本次只在隔离测试目录验证覆盖，未实际覆盖用户技能。按授权将整次 Git 仓库改造相关变更创建本地提交，不执行发布。

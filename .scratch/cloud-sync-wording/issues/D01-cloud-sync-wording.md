# 将多设备备份入口改为云端同步

## Comments

- 用户最终明确要求修改文案，以「同步」表达多端功能，并授权完成后本地提交。
- 已核对连接、手动同步、自动调度、冲突、快照恢复与断开流程：底层复用 Git 获取、提交、合并和推送，应用负责调度与技能级冲突处理。
- 审查发现本机无改动时不主动轮询远端，刷新中的 fetch 失败也会被忽略；本任务只修正文案，远端轮询及刷新错误状态需独立处理。同步状态说明改为与上次获取的云端版本比较，避免承诺已实时检查。

## Result

- 侧栏采用同步图标，三语入口和页面统一为「云端同步」；主操作、自动执行、设置、首次引导、冲突跳转和返回入口使用一致名称。
- 同步状态区分本机待上传文件、待上传提交、云端提交；说明状态与上次获取的云端版本比较。目录标为「本地同步仓库」，与云端地址区分。
- 保留历史快照、恢复和安全副本的含义；连接成功不再误称已恢复，空历史说明手动同步按需创建快照，自动同步保存提交。
- [帮助文章](../../../docs/help/zh/guides/backup-sync.md) 补充连接、立即同步、检查并同步、刷新、自动触发、冲突、恢复与断开的完整流程及当前调度边界。
- 更新既有文件列表和设置测试中的显示名称；全量前端测试 85 个文件、466 项通过（本机使用 `NODE_OPTIONS="--no-experimental-webstorage"`），lint、构建、帮助内容校验、相关文件格式和差异检查通过。构建保留已有 Browserslist 数据过期和大 chunk 提示。
- Standards：复用翻译键与现有组件，不修改路由、设置键、Rust、存储或 Git 同步行为。Spec：以多端同步为主线统一三语文案，并同步 CHANGELOG。
- 未进行原生桌面明暗主题、缩放和键盘验收；本次不执行 Rust 检查或发布。用户已授权本地提交。

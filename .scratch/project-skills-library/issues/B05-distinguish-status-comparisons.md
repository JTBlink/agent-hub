# 区分项目技能的内容比较与管理记录变化

## Scope

用户截图中同一技能同时出现“项目技能内容已修改”和“与中心一致”。前者比较项目内容与管理清单记录的指纹，后者比较扫描内容与个人技能库；入口正常时不应因管理记录变化建议恢复 Agent。

## Acceptance

- 个人技能库一致状态明确比较对象，简中、英文和繁中语义一致。
- 项目管理记录变化、实际 Agent 入口正常时，不显示恢复提示，不计入共享警告，也不提升排序优先级。
- 实际 Agent 入口异常时继续提示具体原因并保留恢复操作；同时发生项目内容变化时说明相对于上次管理记录。
- 卡片与列表使用相同规则，保留未添加 Agent 和独立修改保护的既有行为。

## Comments

- 后端 `modified` 比较项目全目录指纹与清单 `content_hash`；`stale_targets` 检查实际入口相对于当前项目版本的状态。链接会直接读取更新后的项目内容，两种状态不能视为同一恢复条件。
- 本次复用后端既有入口诊断和前端共享判断，不修改项目文件、清单或部署流程。
- 用户后续授权创建本地提交，本轮无远端推送或发布要求。

## Result

- [共享判断](../../../src/lib/projectSkillEntries.ts)仅根据实际异常入口判断是否需要恢复；正常入口不因管理记录变化而触发恢复提示、共享警告或优先排序。
- [状态组件](../../../src/components/ProjectSkillTeamStatus.tsx)始终优先表达需要处理的 Agent 入口；项目变更说明明确比较的是上次管理记录。三种语言的一致标签明确比较个人技能库，卡片、列表与详情共用。
- 回归覆盖三种语言、卡片和列表、管理记录变化且入口正常、记录变化且入口异常、共享警告计数及排序。
- `npm test`：83 文件、447 项通过；`npm run lint`、`npm run build` 通过。首次构建因测试和构建同时生成帮助目录发生冲突，等待测试完成后顺序重跑构建通过。
- Standards：复用既有入口诊断，不修改部署或覆盖保护；Spec：消除正常入口的恢复误报，保留真实异常操作，明确两种比较对象。
- 未进行桌面原生主题、缩放和键盘人工验收；本轮仅修改前端展示规则和文案，未执行 Rust 检查或发布。

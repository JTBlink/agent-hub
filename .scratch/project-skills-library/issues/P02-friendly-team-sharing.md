# 项目技能管理与团队使用解耦

## Scope

团队不强制安装 AgentHub。以项目内技能和 Agent 原生目录为交付内容，将管理清单标为可选共享，降低 Git 忽略提示噪声，并明确普通 Git 维护流程。实现遵循 ADR-0011，保留来源管理与修改保护，不自动修改忽略规则或接管无清单的技能。

## Acceptance

- 不提交管理清单、无个人库时，真实 Git clone 仍取得完整的公共技能和 Agent 原生副本。
- 技能路径与可选清单分开展示、计数；仅清单被忽略不显示技能交付警告。
- 整目录忽略不逐个展开全部子文件；单独资源被忽略仍能诊断。
- 已跟踪文件不误报，新添加的忽略文件仍提示；技能路径可复制，长路径和详情可折叠。
- 部署窗口显示目标项目与团队共享效果；本机未安装的 Agent 可选，部分失败保留失败项供重试，链接工作空间不误提示 Git 团队交付。
- 三语文案同步，前后端回归、构建与静态检查通过。

## Comments

- 用户要求优化项目级 Skill 设计，明确团队成员可能不使用 AgentHub；工具是维护者的可选增强，Git 和原生技能内容是使用基础。
- 不改变已有清单生成行为。清单缺失的成员仍能使用技能，自动来源维护和托管入口管理需由持有清单的维护者执行。

## Result

- [共享面板](../../../src/components/ProjectSharingFiles.tsx)将技能路径与管理清单分开计数和展示，支持复制技能路径、折叠忽略详情及处理建议；三语同步。
- [部署窗口](../../../src/components/AddSkillsSheet.tsx)显示目标项目、团队目标及共享效果；仅移除安装成功项的选择，失败项可直接重试；链接工作空间不显示团队 Git 承诺。
- [Git 诊断](../../../src-tauri/src/core/project_library/git.rs)基于未跟踪的被忽略文件聚合目录，忽略已跟踪文件和空目录；状态读取规范化项目根路径，修复路径别名导致 Git 检查漏报。
- 核心回归 20 项通过，含真实 Git clone 不提交管理清单且移除个人来源后仍可读取完整技能、副本及脚本；整目录忽略、内部资源忽略、已跟踪文件及新资源覆盖。
- `npm test`：206 项通过；`npm run lint`、`npm run build` 通过。构建仍提示既有 Browserslist 数据陈旧及 chunk 大小告警。
- `cargo test --manifest-path src-tauri/Cargo.toml`：654 项库测试通过、8 项忽略，8 项 CLI 测试通过；Rust 格式与严格 Clippy 通过。
- 改动文件 Prettier、`git diff HEAD --check` 通过。Standards 复查确认路径规则与项目内容保护保留，Spec 复查确认原生文件可独立消费，管理文件不是交付前提。
- 浏览器实际检查通过模拟 IPC [示例页面](../../../tests/browser/project-team-sharing.html)：选择技能、部署到未安装 Agent、返回共享面板、折叠和展开路径、复制技能路径、浅色与深色展示，无浏览器运行错误；未调用真实项目写入。窄窗口、文字缩放和原生宿主加载未做人工验收。
- 清单仍供使用 AgentHub 的维护者保留。Git 放行和提交保持显式人工操作，不自动改变项目忽略规则或提交内容。

- 全部本地改动一起提交前复核：前端 48 文件、209 项通过，Rust 库 654 项、CLI 8 项通过（8 项忽略），构建、lint、Rust 格式与严格 Clippy 通过。仓库内可选项目管理清单一并保留，不含个人路径或来源凭据。

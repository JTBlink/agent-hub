# 项目技能库与团队协作：评审范围

状态：首轮已完成。用户已授权修改代码及提交、推送。

## 需求

团队通过项目 Git 仓库共享 Skill 内容；项目使用的版本不依赖维护者个人中央库。多个 Agent 使用同一项目内容，来源更新和入口重建需保护项目本地修改。

维护者安装并提交后，新成员只需 clone/pull 并使用团队支持的 Agent；不要求安装 AgentHub、恢复本机数据库、导入个人库或重新下载 Skill。公共目录直接读取，专属目录默认提交复制副本；项目内链接仅为团队可选策略。

## 设计原文

参见[项目技能库与团队协作方案](../../docs/plans/agent-hub.md#项目技能库与团队协作方案)。实施分期、兼容性、验收、迁移及非目标统一维护于该节。

## 评审焦点

- 项目公共目录与共享可见性；不承诺逐 Agent 独立隔离。
- 来源清单及 AgentHub 元数据布局、固定修订与外部 CLI 兼容范围。
- 停用内容目录及可选链接的目标平台范围；默认内容与团队专属副本提交 Git。
- 团队支持目标不受维护者本机安装检测限制；个人偏好不能改写团队文件。
- 普通项目优先；链接工作空间与全局技能库维持现有语义。
- 文件发布与数据库索引的恢复契约、逐目标失败结果。

## 执行状态

首轮范围采用 [ADR-0010](../../docs/adr/0010-project-skills-library.md)。执行任务：[P01](issues/P01-team-project-install.md)。最低交付包含新成员拉取即可使用、项目入口修复及更新安全；来源固定修订下载恢复和旧项目批量迁移保持后续阶段。

首轮使用 AgentHub 项目清单，外部 `skills-lock.json` 互操作和可选链接不在当前实现内。项目筛选遵循用户最新要求，仅显示检测到安装的 Agent；团队部署目标选择与筛选相互独立。

## 团队友好性修订

按 [ADR-0011](../../docs/adr/0011-optional-project-management.md)，团队不强制安装 AgentHub，管理清单可选共享。项目技能与 Agent 原生入口是使用基础；维护者可用 AgentHub 增强来源维护和修改保护。共享面板分开展示交付内容与管理信息，收拢忽略目录提示且保留单个资源诊断。执行任务：[P02](issues/P02-friendly-team-sharing.md)。

## 桌面目标选择修订

用户要求桌面项目添加从已启用 Agent 中选择，按 [ADR-0012](../../docs/adr/0012-enabled-project-agent-selection.md) 使用本机启用状态生成选项并校正默认和历史选择。项目 DTO 的支持能力与本机偏好分开，核心部署和 CLI 保留完整适配器能力。任务：[P05](issues/P05-enabled-team-agents.md)。

## 项目中央安装修订

按 [ADR-0012](../../docs/adr/0012-project-central-installation.md)，项目中央仓库使用 `.agents/skills` 的实际内容，已有项目版本优先复用。新专属入口默认相对链接、支持复制选项；显式安装可转换指向当前来源的旧中央个人链接，不覆盖其他来源或修改。已有 npx skills 项目相对入口可识别，批量按 Skill 一次生成 Agent 入口。任务：[P04](issues/P04-project-central-install.md)。

“按 Agent 启用/停用”批量窗口同样复用个人可用目标及公共过滤，避免再次展示完整支持列表；目标停用或消失后清理旧选择，两个模式均适用。任务：[P06](issues/P06-batch-enabled-agent-selection.md)。

## Git 忽略诊断修订

共享诊断只提示必要技能内容被忽略的风险。排除 Python 缓存、系统生成文件与本机环境配置（`.env`、`.env.*`、`*.env`），保留 example/sample/template 配置模板、脚本和资料的诊断；不改写 Git 规则，也不改变部署与修改保护指纹。任务：[B02](issues/B02-ignored-local-artifacts.md)。

## 共享信息层级修订

项目顶部的共享说明、路径和管理清单默认折叠为一行，摘要显示警告及错误数量，标题按警告/错误着色，错误优先；展开后直接显示所有详情，不再二次折叠。逐技能的变化与刷新操作放到对应卡片及列表行，按目录关联；需要更新或刷新的技能优先展示，刷新后重新读取状态。任务：[P07](issues/P07-card-team-refresh.md)。

## 统一部署偏好与入口诊断

全局、链接工作空间和普通项目的新 Agent 入口共用默认部署方式；项目中央内容仍为实际文件。未主动选择统一值时保留旧范围设置，已有入口不随默认值切换。安装单次参数可覆盖默认值；异常入口报告 Agent、路径及具体原因，修复沿用文件保护。任务：[P08](issues/P08-unified-deployment-mode.md)。

## 未登记入口移除修订

项目中央技能已经管理时，按 Agent 移除也必须处理实际存在但未记入清单的旧专属入口。个人与项目相对链接只删除入口本身，未修改副本沿用内容保护；公共目录不允许单 Agent 移除。任务：[B03](issues/B03-unrecorded-agent-removal.md)。

## Agent 技能状态文案修订

未添加的灰色 Agent 是正常状态，即使历史清单仍有记录，也不显示入口缺失提示。恢复操作只更新实际存在的入口，不自动添加不存在的目标；添加由用户点击 Agent 图标或显式部署执行。已有入口的链接或副本差异逐项解释，并保留独立修改保护。任务：[B04](issues/B04-clear-agent-skill-status.md)。

项目内容相对管理清单中的上次记录有变更，不代表实际 Agent 入口需要恢复；只在实际入口存在链接或内容异常时显示恢复提示、计入共享警告并优先排序。个人技能库比较独立保留，并明确显示“与个人技能库一致”。任务：[B05](issues/B05-distinguish-status-comparisons.md)。

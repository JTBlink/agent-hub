# Skills Manager 后续集成备选方案

本文保留前期分析供后续参考，不属于当前实施范围，也不是已接受的架构决策。当前仅整体导入独立模块，见 [当前规格](spec.md)。

状态：建议方案，尚未进入实现。评估日期：2026-10-04。

代码基线：AgentHub `f04487a`；相邻 Skills Manager 仓库 `def946d`。
本次为本地代码与数据结构审查，未运行两套应用、构建或数据迁移实验。

## 结论与范围

可以合并。AgentHub 是模块化主应用，Skills 是其中一个业务模块；将 Skills Manager 的完整技能管理业务作为该模块的实现基础，保留已有能力，通过适配接入主应用。

整体范围包括技能库、来源发现、标签、Preset、多 Agent/工作空间部署、版本更新、CLI、备份与同步。实施可以分阶段验证，但这些能力都属于合并范围，不把原有功能默认裁剪成后续可选需求。

AgentHub 保留应用外壳、配置管理、工作空间身份及其他模块。Skills Manager 的独立桌面壳、全局导航、应用更新、托盘与发布入口由 AgentHub 对应设施接管。原 AgentHub 的 Skills 实现逐步被统一模块替换；现有来源追踪、确认计划、诊断和回滚行为通过适配继续提供。

一个主应用和一个 Skills 写入方是目标；物理上只有一个数据库文件不是前提。Skills 模块可以拥有独立数据库与 migration，配置模块继续使用原存储；通过服务接口与稳定 ID 协作，禁止跨模块直接写表。

## 目标模型与边界

以下为待 D01 落实的模型设计，不替代现有已接受 ADR。

1. AgentHub 壳负责导航、窗口、主题、语言、应用更新和公共工作空间身份。Skills 模块拥有自己的页面、状态、业务服务、持久化、任务和备份；不得把技能专属依赖反向扩散到配置模块。
2. 模块以 Skills Manager 的 `SkillRecord`、目标、Preset、标签和同步协议为实现基础，保留稳定 ID。对主应用提供来源、描述和安装实例的契约适配；补足 AgentHub 所需的来源版本、指纹、作用域及确认计划，禁止按名称粗暴合并身份。
3. 推荐将模块私有文件放入 `~/.agenthub/modules/skills/`，由注入的路径上下文决定。独立 SQLite 可保留原 schema 并增量扩展；不得直接打开旧库运行启动迁移。公共 Workspace ID 在模块中保存映射，不跨库建立外键或假定跨库原子提交。
4. 既有多 Agent、自定义路径、Preset 与复制/链接能力均保留。公共配置页面仍只展示已经实现配置适配的 Agent；支持安装 Skills 不等于支持配置编辑。
5. 所有技能写操作最终只由一个模块服务执行，原 AgentHub Skills command 改为门面或在完成兼容迁移后退役。预览到执行之间重验身份、指纹和授权，批量失败有持久化操作日志及补偿；恢复失败保留备份和诊断。
6. 旧安装的复制/链接模式保持，切换模式需显式计划。对可变中央库链接，更新计划需列出全部受影响目标并定义撤销语义；是否改为固定快照由 ADR 确定，不能默认移除原链接能力。
7. Skills 页内保留库、发现、Preset、部署、备份和模块设置等子入口。原 dashboard 中技能专属信息进入模块首页；应用级设置、窗口和版本升级功能接入主应用。

建议模块方向（随具体切片渐进落地）：

```text
src/modules/skills/
  pages/           原业务页面的模块化版本
  components/      模块组件
  state/           模块 Provider，桥接主题和语言
  api/             模块 bindings 与兼容接口
src-tauri/src/modules/skills/
  service/         技能库、来源、Preset、部署服务
  storage/         模块数据库与 migration
  integration/     AgentHub 契约、Workspace/Agent ID 映射
  migration/       两边旧数据读取、计划和恢复
  backup/          原快照、同步、对象合并能力
  commands/        模块 command，统一命名空间
src-tauri/src/bin/ CLI，共用 Skills 模块服务
```

最小宿主接口包括路径、工作空间解析、主题/语言设置、模块事件及受控启动/停止。文件监听与后台任务随主应用生命周期管理，防止切换页面重复启动。CLI 通过无窗口的服务接口复用业务。模块进入已授权后台同步模式后，仍需遵守该模式的明确范围和冲突保护。

## 旧数据导入流程

1. 用户选择旧库位置，兼容默认 `~/.skills-manager/`、已迁移的中央库及外部 skills root。解析旧配置只为定位，不调用旧应用启动初始化器，避免触发自动迁移、重建或同步。
2. 使用一致的只读 SQLite 快照读取旧记录，注意 WAL；扫描文件并在复制前后核对修订。旧应用仍在修改时使计划失效并重试，不以单独复制主 DB 文件替代一致快照。
3. 同时支持 AgentHub 原技能来源、安装表和 marker 的迁移。配置数据原位保留。展示导入数量、标签、Preset、缺失来源、重复内容、同名不同源、无效链接、未知 Agent/作用域。默认只导入技能库与元数据，不接管 Agent 目录。
4. 根据模块选定的版本化指纹规则重新校验内容。两边散列算法、忽略项及权限处理不同，hash 必须保留算法来源，不跨算法直接比较或作为覆盖授权。
5. 以旧库身份、旧 Skill ID 和迁移映射保证重复执行幂等。相同来源但存在本地修改的内容保留为不同快照；同名不同源必须保持独立。无法还原来源时登记为本地导入，不猜测 Git revision。
6. 项目路径先 canonicalize，再映射到公共 Workspace；无法访问的路径保留为待映射记录。模块 Agent key 与公共身份显式映射，例如 `claude_code ↔ claude-code`。未知 Agent 保留原始引用和待映射状态，不静默丢弃或自动部署。
7. 文件先进入 staging，持久化操作日志与 ID 映射，再提交库条目、标签和 Preset。异常可重试、可恢复；原数据库、中央库及 Agent 目录保持可用。
8. 导入完成后，再由独立安装计划处理部署。已有旧系统复制目录或软链接作为外部管理目标展示；接管需单独预览、备份、确认和所有权校验，不能仅补写一个 AgentHub marker。
9. 迁移回滚只撤销本次新建数据和有证据属于本次的文件。若导入后发生编辑或新安装，应提示冲突并保留用户新状态。旧应用与 AgentHub 不得同时接管同一目标；跨应用锁不兼容时必须通过关闭旧应用及执行前重验控制切换。

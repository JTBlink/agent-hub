# B23：减少 Git 备份凭证的重复钥匙串弹窗

Type: task
Status: resolved
Blocked by: none

## Scope

检查 Git 备份凭证读取与开发构建签名。进程内共享凭证读取结果，合并并发读取；登录与退出立即更新缓存，拒绝授权后避免后台反复弹窗。保留 OS 钥匙串存储和系统授权边界。

## Acceptance

- 用隔离后端计数验证重复读取、并发读取、拒绝与凭证变更，不读取真实钥匙串。
- 说明开发版签名变化仍可能需要系统重新授权，不承诺绕过 macOS。
- 更新文档、CHANGELOG 并通过 Rust 测试、格式与严格 Clippy。

## Result

Git 凭证每次读取都会访问 OS 钥匙串，缺少进程内复用；当前开发二进制确认是 ad-hoc 签名。新增共享会话缓存，成功、无记录及读取失败均复用，并发访问合并；成功登录、更新、退出即时更新缓存。没有把凭证写入文件，也没有放宽钥匙串访问控制。

回归：修改前 3 次读取触发 3 次后端访问（预期 1），修改后通过；并发拒绝仅访问一次、令牌轮换和退出同步更新均通过。完整 Rust 测试、格式及严格 Clippy 通过。开发版每次重编译或独立 CLI 进程仍可能需要首次系统授权，文档明确说明稳定签名要求。

## Review

- Standards：钥匙串仍为持久化凭证来源，缓存只存进程内，不序列化、不打印秘密；授权失败不会反复申请。
- Spec：减少同一会话重复弹窗，不宣称绕过首次 macOS 授权或解决签名证书缺失。

## Follow-up

开发构建现在默认不启动会读取备份钥匙串的后台任务，也不执行启动凭证迁移；临时签名每次重编译不会再触发重复授权。需要在开发版联调时设置 `AGENT_HUB_DEV_KEYCHAIN=1`。

本次提交前验证：完整工作区 `cargo test`（592 项通过、8 项忽略）、`cargo fmt --all -- --check` 与严格 Clippy 通过。审查确认开发默认关闭后台访问，显式开启与正式构建保留原有流程。

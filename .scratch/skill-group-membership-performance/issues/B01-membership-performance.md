# B01：优化加入与移出技能组

Type: task
Status: resolved
Blocked by: none

## 原因

原操作逐技能执行 IPC，每次遍历导出全库同步元数据并同步刷新托盘。结束后全量读取 Skill、扫描项目；技能列表变更还会触发备份状态扫描。备份投影持有相同仓库锁，可能拖慢后续点击。

## Result

- 将成员 commands 抽到独立模块，单项和批量共享事务及分组元数据写入。
- 元数据导出只处理当前组，复用原序列化/原子写入；组内序号仍完整重算，删除持久化，缺少快照时回退完整导出。
- 前端复用独立 hook，批量只发一条命令；成员 ID 回读仅修补成员关系与计数。成员变化不触发全库/项目/备份扫描，备份提示立即标记待同步。
- 抑制本次元数据写入的监听回声，保留自动备份通知；托盘沿用合并刷新。

隔离 fixture：128 个库内技能、加入 20 个，原逐项后端路径约 362ms；优化后逐项约 196ms，批量约 157–175ms（约缩短 52–57%）。这是本机后端测量，不包含真实用户库的扫描/托盘/UI 时间。

## 验证

- 原实现的回归测试先失败：成员操作会重新导出无关技能记录；修复后通过。
- 3 项 Rust 回归覆盖无关元数据不变、批量失败回滚、元数据初始化、增删重建、排序、Agent 开关和其它组保护。
- 3 项前端回归覆盖成员补丁、成员变化不重启备份扫描的依赖键、批量单 IPC。
- `npm run build` 通过；`npm test` 75 项通过；修改范围 ESLint 与 Prettier 通过。
- `cargo test --manifest-path src-tauri/Cargo.toml -- --test-threads=1`：619 项库测试及 7 项 CLI 测试通过，8 项忽略。默认并行运行曾出现共享目录测试失败，串行完整运行通过。
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`、修改范围 Rust 格式检查、`npm run tasks:check` 与 `git diff --check` 通过。
- 全仓 `npm run lint` 被未改动的 `ProjectDetail.tsx` 两处 `set-state-in-effect` 错误阻塞；全仓 Rust 格式检查发现其它在途修改的格式差异。

## Review

Standards：按成员命令、数据库事务、元数据持久化和前端交互拆分，保留仓库锁与原子文件写入；不增加真实个人信息或安装目标。

Spec：成员编辑不部署；批量失败数据库回滚，元数据失败仍回读数据库以修复界面。保留组内排序与恢复语义，不使用“只写新增成员”而遗漏其它成员序号变化。

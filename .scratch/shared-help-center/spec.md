# 共享帮助中心

Type: feature
Status: resolved

## Problem Statement

帮助正文与界面翻译混在一起，固定卡片难以承载持续增长的文章；产品网站与桌面帮助分别维护，用户不能分享具体操作说明。

## Solution

建立 Git 管理的 Markdown 内容库，以稳定文章标识连接应用离线帮助与 VitePress 文档站。帮助首页提供分类和搜索，文章支持目录、内部跳转、相关文章及在线分享。构建统一校验内容，网站随现有 Pages 工作流发布。

## User Stories

1. 作为新用户，我希望找到快速开始，以完成首次导入和部署。
2. 作为使用者，我希望按任务浏览分类，以找到项目、技能组和备份说明。
3. 作为使用者，我希望搜索中文标题和正文，以找到具体问题。
4. 作为离线使用者，我希望阅读随应用提供的文档，以了解当前版本。
5. 作为使用者，我希望文章内的链接与图片在应用和网站都可用。
6. 作为使用者，我希望通过文章目录定位操作步骤。
7. 作为使用者，我希望分享具体文章及其章节。
8. 作为多语言使用者，我希望缺少翻译时得到明确的中文回退提示。
9. 作为维护者，我希望新增 Markdown 并安排导航即可添加文章，无需改页面代码。
10. 作为维护者，我希望移动源文件时已分享的网址仍然有效。
11. 作为维护者，我希望重复标识、断链、缺失图片和无效导航在构建前失败。
12. 作为维护者，我希望推荐文章记录核验日期，避免把来源描述当作永久事实。
13. 作为维护者，我希望开发预览、测试和安装包构建自动准备离线文档。
14. 作为维护者，我希望公开站点只包含明确发布的帮助内容，草稿不进入搜索和安装包。

## Implementation Decisions

- 标准 Markdown/GFM 是唯一正文来源；网页使用 VitePress 稳定版，应用保留 React 和现有语义主题。
- 分类和推荐顺序由一个导航配置维护；元数据包含稳定 id、标题、摘要、标签、适用起始版本及可选关联文章、别名和核验日期。
- 构建入口扫描、校验并生成同一文档清单；网站与应用分别呈现，内容、标题锚点和内部链接规则共用。
- 首期完整提供中文正文；其他语言逐篇扩充，缺失时回退中文并提示。按钮和界面说明保持三语。
- 应用文档包含构建版本，随安装包离线交付；网站明确展示对应构建版本，不声称提供尚未实现的历史版本切换。
- 内部链接使用稳定标识生成路由；源路径可以移动，旧标识由显式别名保留。
- 网站与原产品首页合并为一次 Pages artifact；保留版本 tag 和手动触发，不擅自增加普通分支自动发布。
- 中文搜索同时支持词语与连续子串；初期使用本地索引，不接入外部搜索服务。
- 生成目录与索引不提交，全部从内容源重新构建；不嵌入 Vue、HTML 或脚本到共享正文。

## Testing Decisions

- 内容构建公开入口：在临时目录放入真实 Markdown，验证文章、锚点、图片及网站输入与离线包一致，并验证无效内容阻止构建。
- 应用帮助页面：通过路由和 DOM 验证搜索、内部跳转、目录、翻译回退、分享及未知文章恢复；只替换外部 opener 和剪贴板接口。
- 发布构建：验证产品首页和文档独立入口、子路径与分享页面，并运行现有工作流合约测试。
- 验证前端全量测试、lint、类型和生产构建；检查明暗主题、窄窗口、键盘及缩放。Rust 无业务变更，按仓库交付要求执行格式、Clippy 和测试。

## Out of Scope

文档自动热更新、CMS、账号系统、AI 问答、全历史版本站点、正式发布与远程部署。

## Further Notes

用户要求先出方案后自动完成，以上实现与测试选择依据前文已讨论方案，不额外等待逐项确认。当前工作区已有其他需求的变更，保持原样并仅处理本需求范围。

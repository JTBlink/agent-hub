# 展示待备份文件

按 [规格](../spec.md) 在状态卡片中展示具体文件更改，并补齐跨端契约和回归测试。

## 验收

- 文件路径和类型清晰可见，完整列表可滚动。
- 已提交未推送、重命名、中文路径和元数据准确展示。
- 远端独有更新不误报；上传完成后不保留旧列表。
- 通过前端测试、lint、构建，以及 Rust 测试、格式和严格 Clippy。

## Comments

- 本次实现保留已有其他任务的改动；用户随后明确授权本功能提交并推送至 main。

## Result

- 状态命令新增完整文件更改列表，由独立 Rust status 模块负责；包含工作区和待推送提交，以共同祖先计算分叉中的本地更改，避免误报远端独有更新。
- 状态卡片新增独立展示组件，列出相对路径和更改类型，支持重命名原路径、长路径换行、完整列表滚动及键盘聚焦；补齐中英繁体文案。
- 技能计数从同一列表派生，不统计元数据或根目录文件；修复旧 porcelain 字符串首行空白裁剪与路径转义可能导致的计数错误。
- 新增 5 项 Rust 行为测试及 2 项前端展示测试，覆盖暂存、未暂存、删除、新文件、中文路径、重命名、待上传提交、首次上传、远端更新、元数据和列表清空。
- `npm test`：83 个文件、441 项通过；`npm run lint`、`npm run build` 通过。
- `cargo test --manifest-path src-tauri/Cargo.toml -- --test-threads=2`：库测试 701 项及 CLI 测试 8 项通过，8 项按原配置忽略。
- Rust 格式检查、严格 Clippy 和 `git diff --check` 通过。
- 实际桌面深色中文备份页面验收通过：现有待备份文件路径及“修改”标签可见，主备份按钮保留。未修改或上传用户技能；未进行浅色主题、放大文字及多文件原生界面的实机验收，这些布局由共享主题 token 和组件测试保障。
- Standards：状态读取与展示各自独立，复用状态命令、锁和刷新流程，仅增补返回字段，无新增依赖或持久化格式修改。
- Spec：具体更改可见，长列表不截断，备份完成清空，远端独有更新不误报；已补充 Unreleased 更新日志。

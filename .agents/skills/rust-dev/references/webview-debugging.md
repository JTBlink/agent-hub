# 桌面 WebView 调试

适用于单测通过但实际桌面窗口仍异常、懒加载功能失效或开发环境依赖错误。先固定具体文件、页面和操作，保留实际失败证据，再修改对应层；jsdom 测试不能验证 WebView 的模块加载和真实着色。

## 选择调试通道

- 先核对实际进程、产品、检出目录、开发 URL 或安装包；同名开发包和安装包可能共用 bundle identifier，绑定完整应用路径，不能凭名称判断运行版本。
- macOS Tauri 主窗口使用 WKWebView，通过 WebKit Inspector 调试；开发构建通常可用 `⌘⌥I` 打开，实际以窗口配置为准。Chromium 预览宿主是另一个进程，不能用它的 Console 代替主窗口诊断。
- Chrome/Chromium 可通过已授权的 CDP 会话检查 DOM、Console 和网络；WKWebView 使用 WebKit Inspector 协议，不能把 Chrome CDP 客户端直接接到主窗口。无已暴露调试连接时，可用现有 GUI 自动化工具打开 Inspector 并操作 Console，无需先部署远程调试服务。
- 用当前可用的工具接口获取窗口与控件状态；观察后再操作，Console 输入前核对焦点，避免诊断代码落入终端或编辑区。用户同时操作窗口时暂停输入，重新确认目标后继续；工具成功返回不等于表达式已执行，须读回结果。

## 从现象定位到运行实例

1. 在实际窗口重现，检查 Console 的异常和 Network 中动态模块的请求。记录错误及状态码；降级为纯文本、空面板等静默 fallback 也可能隐藏加载或挂载错误。
2. 用最小只读表达式区分层次：DOM 是否生成高亮 span、解析器是否注册、语法树是否存在、样式是否应用。动态 import 成功仅证明模块加载成功，不代表扩展已经挂载。
3. 必要时检查真实组件实例。CodeMirror 可通过 `EditorView.findFromDOM(element)` 获取实例，再读取 `state.facet(language)`、`syntaxTree(state)` 和源码行 DOM。导入模块时使用当前开发服务实际转换出的 URL，不能猜版本 query，也不能将新导入模块与旧实例的身份差异直接当作业务缺陷。
4. 只读检查不足时，可对单个只读编辑器做临时挂载探针并捕获异常；说明其内存副作用，结束后销毁或重建该编辑器。禁止在 Console 执行未经核实的远端写入、文件写入或安全配置修改。
5. 修复后在同一文件、同一布局验证用户可见效果，再补充主题、缩放和交互检查。区分测试通过、实际窗口复验、提交和发布。

## CodeMirror / Vite 依赖实例冲突

典型信号：语言模块加载成功，但编辑器没有 language facet、语法树为空；挂载扩展时报 `Unrecognized extension value`，并提示存在多个 `@codemirror/state` 实例。

- 先用依赖树检查安装版本，再核对 Vite 转换后的模块 URL、预构建元数据及共享 chunk。安装树去重不代表浏览器运行时只有一个实例；不同轮次的预构建也可能留下两份构造器。
- 仅预构建懒加载语言包仍可能漏掉编辑器核心入口。核心、语言包及高亮依赖应参与同一轮预构建；复用 `package.json` 与共享语言登记文件，不在多个页面维护独立清单。仅提供子路径的包按其实际导入路径处理，例如 legacy modes 没有包根入口。
- 不将刷新、清缓存或重启当成已修复。先记录失败，再验证当前配置重新加载后是否仍失败；修正配置后重新打开实际文件，确认关键字、字符串等恢复。重载前检查未保存内容和运行会话的影响，不能为观察高亮中断任务。
- 回归应同时覆盖冷启动依赖准备、预构建核心与语言扩展的身份兼容，以及实际 diff 两侧的源码高亮。隔离测试缓存，避免污染运行中的开发服务；测试不得仅验证请求返回 200 或语言包存在。

诊断片段、截图和日志使用合成数据或脱敏信息。临时探针不进入产品代码，结束时关闭调试面板并保留可维护的回归测试。

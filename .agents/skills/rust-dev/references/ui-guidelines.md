# UI 与交互规范

主题 token 以 `src/styles/brand.css`、`tailwind.config.js` 为准。下述交互清单用于新增或修改界面的验收，不要求顺带重写所有历史组件。

## 品牌、主题与样式

- 保留原 Logo 与 `src-tauri/icons/app-icon.svg` 图标母版。平台图标变更查 [图标规范](icon-assets.md)。
- 使用当前工作台布局，沿用 `src/components/Layout.tsx`、`Sidebar.tsx` 与同类页面的结构、密度和层级，不采用旧配置中心原型。
- 使用语义 Tailwind 类与集中变量，不在页面硬编码另一套品牌配色。需要新语义 token 时先检查现有 token，再集中定义并适配明暗主题。

| 用途             | 现有语义类示例                                                  |
| ---------------- | --------------------------------------------------------------- |
| 页面与次级背景   | `bg-background`、`bg-bg-secondary`                              |
| 卡片、悬停、选中 | `bg-surface`、`hover:bg-surface-hover`、`bg-surface-active`     |
| 边框             | `border-border`、`border-border-subtle`                         |
| 文本层级         | `text-primary`、`text-secondary`、`text-tertiary`、`text-muted` |
| 主操作           | `bg-accent`、`text-accent-light`、`border-accent-border`        |
| 危险操作         | `text-danger`、`bg-danger-bg`                                   |
| 卡片阴影         | `shadow-card`、`shadow-card-hover`                              |

- 深色基线为背景 `#08101f`、卡片 `#111d35`、边框 `#263b67`、主色 `#168bff`，辅助色青 `#42d9b1` 与紫 `#9b9cff`。这些值用于识别品牌，实际样式引用 token，以保留浅色主题和跟随系统能力。
- 保留文字缩放。沿用现有字体、间距、圆角和图标风格；没有明确重设计需求时不引入第二套组件体系或新的全局视觉语言。

## 组件与信息层级

- 先查 `src/components/` 与同类页面。开关优先复用 `ToggleSwitch`；错误、空状态、弹窗和详情面板检查已有实现，复用时同时检查其主题和可访问性是否满足当前需求。
- 页面壳负责组合；列表行、详情面板、空状态、弹窗、向导按职责拆分。共享状态标签、Agent 图标、技能组展示规则来自现有纯函数或定义。
- 清晰区分主操作、次级操作、危险操作。长路径或名称不能挤掉操作区；截断时仍提供查看完整内容的途径。
- 空列表、筛选无结果和读取失败表达不同原因，并在有合理下一步时给出操作入口。

## 弹出菜单与主题一致性

- 应用内筛选、表单与弹窗使用 [ThemedSelect](../../../../src/components/ThemedSelect.tsx) 等共享菜单，不能让可见的原生 `<select>` 弹出不随主题变化的系统菜单。隐藏的原生表单值桥接可以保留；文件选择、系统授权等原生系统对话框遵循平台样式。
- 下拉面板、右键菜单及动作菜单均使用当前主题的 `bg-surface`、边框、文字与悬停 token；选中标记、禁用项与键盘活动项有明确区别。不得只修改触发按钮而遗漏弹出面板。
- 溢出滚动容器中的菜单使用 portal，按 `getAppScale()` 把 `getBoundingClientRect()` 坐标换算为应用坐标；需要处理向上展开、窗口边缘、滚动与尺寸改变。不要把原始视口坐标直接用于缩放页面的 fixed 元素。
- 单选菜单支持方向键、Home/End、Enter/Space、Escape、Tab、外部点击和焦点恢复。嵌套于弹窗时，第一次 Escape 先收起菜单，再按 Escape 才关闭弹窗。
- 模态窗口最大高度按 `100vh / var(--app-scale)` 计算可用空间，内容区内部滚动，标题和底部操作可达；不能以未换算的 `vh` 限高后把底部按钮挤出视口。
- 新增或调整菜单时，实际打开检查深色/浅色、默认/放大字号、窄窗口、长标签和视口边缘。组件测试覆盖选择值、取消不修改、禁用与焦点，不以颜色类名断言代替交互测试。

## 交互验收清单

- **状态反馈**：按业务覆盖初始、加载、有数据、空、失败和成功状态；请求中阻止重复提交，失败保留可重试信息或已填写内容。
- **异步一致性**：切换项目、技能或筛选后，旧响应不覆盖当前目标；开关与批量操作的等待状态能明确归属于实际目标。
- **数据操作**：删除、覆盖等沿用现有确认和恢复流程；隐藏按钮不能代替后端校验。
- **键盘与焦点**：可交互元素可用键盘到达，有可见焦点；开关提供状态，纯图标按钮提供可访问名称。弹窗检查初始焦点、焦点约束和关闭后焦点恢复，Escape 行为与当前业务一致。
- **可理解状态**：状态不只靠颜色传达，结合文案或图标。加载与错误反馈不能遮住恢复入口。
- **布局适配**：检查明暗主题、跟随系统、文字放大、窄窗口、长中英文文案和滚动区域，保证关键操作可见可达。

## 文案与国际化

- 新增 UI 文案同步更新 `src/i18n/zh.json`、`en.json`、`zh-TW.json`，复用已有 key，不将界面文案散落在组件中。
- 采用 `CONTEXT.md` 术语：中文“技能组”、英文“Skill Group”；导入技能库、部署到工作空间和组成员关系是不同操作，文案应表达实际效果。
- 本地化只影响展示，不改写用户自定义名称、数据库 ID 或持久化字段。
- 错误说明用户能采取的动作。技术细节在有助于定位或处理时展示，避免把内部模块与实现过程写入正常产品流程。

UI 验收记录应区分自动测试和实际界面检查；无法启动应用时列出未验收的主题、缩放或键盘行为，不能声称已经通过。

共享控件 API、状态与拆分要求见[组件规范](component-guidelines.md)。

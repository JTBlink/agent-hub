# 报告与运行状态

## 报告与重复检查

报告保存在 `.local/state/reviews/`，按平台、主机、仓库、编号分别记录最近一次审核。只有报告属于本轮 head/base、包含两个轴的实际结论，且结束时请求仍开放、非草稿、提交未变，才记录该版本已审。相同 head/base 和目标分支不重复启动 Agent；源分支或目标分支出现新提交时重新审核。失败、缺少报告、受阻和版本变化不记录已审，未完成报告保留于本地以便排查。

已有远端 Review 不自动认领为本任务结果；新安装的任务首次遇到请求仍会审核。平台评论或规格在相同提交上变化不会自动使本地结果失效；需要重审时删除该请求对应的本地已审报告。报告和运行状态不进入任务定义或 Git 备份。

## Herdr 执行

每个任务复用固定标签页，不抢占焦点；每轮启动全新 Agent。上次仍在工作时跳过，不排队或重复投递；等待输入、投递不明确或超时保留会话，不自动回答审批。只有出现可验证的本轮审查报告才记录已审，Agent 回到就绪状态不代表审核成功。

提示词投递一次后最多观察 30 分钟；Herdr 服务须保持运行，AgentHub 关闭后系统日程仍有效。恢复时先在 Herdr 检查原会话，再处理 `.local/state/.herdr-run.json`，不要在任务仍工作时清除状态。

`config/herdr.json` 的 `agent`、`arguments` 和 `extra_arguments` 沿用所选 Agent 的启动配置。Codex 默认以无人值守参数启动，额外参数按 argv 追加，不经过 Shell。没有运行中的目标会话时报告错误，不创建或重启服务。

## 兼容性

任务包版本为 `2.0.0`，从“修复并推送 MR”改为“仅审查 PR/MR”。目录和模板 ID 仍为 `agent-mr-processing`，旧名称仍可解析到该稳定目录。升级模板不会自动覆盖已安装任务的自定义内容；已有任务需明确更新定义和入口后才使用新流程。名称变更不搬迁已有包目录，也不自动启用暂停的任务。

# 恢复不变量与验收

用于旧批次阻塞、资源泄漏、送达不明及恢复后无业务进展；配合
[自动化巡检](automation-maintenance.md)，不替代任务原生协议与业务 Skill。

## 原执行权与停滞

- 同时读任务运行记录、原 Agent 身份、批次回执和权威租约。区分真实业务写入者、
  远端仍运行的 Job，以及等待它们的父进程、Worker/CLI 包装器；后者不能被列成
  “必须先停止的业务写入者”，形成互等。
- 同时看总运行时间和阶段内无进展时间。新产物、目标变化、回调和远端 Job 前进
  是实际进展；屏幕刷新、重复重试不是。不能因总时长超限重启仍有进展的执行者，
  也不能无限以 `working` 跳过诊断。
- 业务对象已关闭或结束，仍要扫描已登记待清理项，不能只枚举开放对象。
  关闭不等于已交付；清理不授权重开对象或删除未合入成果。

## 旧输入与资源交接

- 新版本到达，先核实旧批阶段及未决写入。已停写、只读且未领取修复的旧诊断，
  可沿原生过期入口归档；有修复领取、租约或写入不明的，须由原执行者收齐结果并
  交接。不能仅凭版本变化丢弃旧 run、清零额度或解除租约。
- 回调用原批 request/run/source/base，新版本成果记录实际版本。已完成批次只保留
  历史，不伪造新的领取或重复原回调来结束一次续作。
- 未改代码、来源被他人推进，按原协议记录 superseded 及未写入事实，再释放资源。
  协议要求交接评论时先读回；不能拿旧来源 CI 结论签发新版本通过。
- 目录含未交付提交，先核实并保全独立恢复引用，再按原生流程清理。固定目录、
  兼容缓存和历史保留；不按名字删除目录，不手改状态制造“已释放”。

## 输入与写入

- 恢复消息携带准确批次身份、当前问题及版本证据。先核实 pane/会话/cwd 归属和
  已有送达回执；重复投递和 `requested` 都不等于业务已开始。
- 原生终端可能解释输入前缀。例如 Codex TUI 把以 `!` 开头的文本作为 shell 执行；
  业务说明用普通文字开头，不能直接以 MR 的 `!编号` 开头。优先用共享执行器的
  结构化续作入口，从新屏幕或回执确认实际送达。
- 前置条件失败即停止依赖写入。断言和后续写命令不能放在失败仍继续的 shell
  序列中；使用独立工具步骤、返回码检查或正确的失败即停控制。保存仍用原 revision，
  并发变化先比较，不替换令牌后强写。
- 执行器的 grant/nonce、validated/journal 和验收凭证只由原生执行器在真实检查后
  生成。不得仿造许可文件、手改状态、关闭保护或拼内部步骤冒充完整验证。
  已发生的不规范步骤保留审计，最终恢复不能抹去中间事实。
- 观察避免无关写入：Git 状态读取可设 `GIT_OPTIONAL_LOCKS=0`；不删除未知 index.lock。
  实际 cwd、解释器及命令参数从当前记录和帮助核实，不拼接历史路径。脱敏同时覆盖
  `token=value`、`--token value` 和认证头。

## 修复生效验收

离线回归覆盖受影响的版本推进、重复送达、旧回调、未决写入、正常等待不重派及
终态清理边界。保留失败复现与转绿结果；文案检查不伪装成行为回归。原 ID 原地
升级，包预算、完整文件、日程、启用和额度分别读回。

运行验证检查原任务是否消费新证据、推进业务并正确收口资源。普通进度字段、
旧失败评论或状态标签不能替代当前权威版本，相关判定由业务 Skill 维护。
HTTP 成功、进程退出 0、派发或保存成功均非业务完成。用户明确持续目标时，以
实际业务终态及必要收尾验收，阶段回调不是整项结束。

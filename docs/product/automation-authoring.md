# 自动化任务编写规范

任务可以只执行普通命令。Agent 是可选能力；需要 Agent 时，统一通过独立启动模块优先使用 Herdr，未安装时自动退化为原生终端执行，不在任务里另写模型调用、进程启动或模拟交互。

## 任务包

遵循 ADR-0016、ADR-0017 和 ADR-0018：`TASK.md` 是说明入口；`config/task.json` 是清单、日程、依赖和文件列表的唯一来源；代码在 `scripts/`，配置在 `config/`，按需资料在 `references/`。本机绑定、依赖环境、检查点和日志只放 `.local/`，不得进入分发和备份。

普通任务只声明实际需要的文件和命令，不需要 `agent.json`、提示词或 Agent。Agent 任务增加 `prompts/prompt.md` 与 `config/agent.json`，提示词只表达目标和约束；执行流程与报告格式优先由已安装 Skill 承担，脚本只提供必要的确定性上下文。

## Agent 选择

自动化编辑器只提供“不使用智能体”和本机已安装、已启用的具体 Agent，名称、图标与排序复用工作区规则，不提供“默认 Agent”选项。选择具体 Agent 后写入对应的 `runner.kind`，后续全局默认 Agent 变更不改变该任务的选择。

旧任务或模板中的 `runner.kind: default` 继续兼容全局默认配置，编辑器显示当前解析出的具体 Agent；只查看或保存其他字段时保留原配置，切换为具体 Agent 后才固定为对应类型。未安装或未启用的既有 Agent 显示为不可用，不静默切换其他 Agent。

## Herdr 模块

任务入口复用 `automations/_shared/agent-entry.py` 薄适配器，通过 `agents launch execute` 调用 `core/agent_execution`。Herdr 专有行为维护于 `core/herdr`，状态事务维护于 `core/state_store`；公共实现随匹配 CLI 管理为单份版本资源，任务不携带 `herdr_agent.py` 或存储实现副本，无需运行桌面进程。业务筛选与结果校验仍由任务自己的脚本负责。

```json
{
  "runner": {
    "kind": "codex",
    "session": "default",
    "title": "Project task"
  },
  "launch": { "arguments": [] },
  "execution": { "wait_timeout_seconds": 1800 }
}
```

- `runner.kind: default` 使用全局默认 Agent；明确的类型使用该 Agent 的全局启动指令。
- `launch.arguments` 是按字面传递的参数数组，追加在全局启动参数之后。每个元素都是一个 argv，不做 Shell 或引号解析。
- `execution.wait_timeout_seconds` 的范围为 60–7200 秒，默认 1800 秒；超时只停止等待并保留会话。
- `execution.session_reuse_seconds` 可选，范围 0–86400 秒，默认 0（每轮换新 Agent）。设为正数时，上一轮已确认完成且原 Agent 空闲、会话未超过该时长，下一轮在原会话继续；超过时长后在原标签页换新 Agent 并重新计时。仍在执行、等待输入或结果不明时照常保留现场，不打断、不重发。
- 模型使用 Agent 自身默认值；平台不要求填写模型。保留已有任务显式参数，不在升级时擅自移除。
- 系统日程只负责触发，Agent 必须在已选择的项目目录运行。Herdr 未安装时通过共享 CLI 创建可见原生终端并保存启动回执；没有系统终端时明确报错。会话或身份不明、仍在运行、审批等待及投递超时均保留原窗格，不重复启动或重发。
- 新包依赖由清单声明。旧版完整脚本保留既有运行兼容；新版薄适配器需要支持共享执行命令的 AgentHub CLI bridge，缺失或过旧时明确报错，不回退到包内另一套实现。

## 超时后的结果收回

控制器停止等待后，原 Agent 可能仍在执行。后续触发可使用 `agents launch reconcile`，从 stdin 提供原批次的 `ExecutionRequest`，保留原状态目录、身份目录和不可变提示词。这个入口只观察已有执行并收回确认完成的结果，不新建面板、启动 Agent 或投递提示词；面板关闭、身份改变或证据不足时保留检查点，不能改用 `execute` 重跑。

仅收回执行结果不代表业务通过。任务仍须验证原批次的 run_id、来源/目标版本、结果回调及适用的标签和修复证据，保留累计次数及人工接管记录，再决定是否允许下一轮。旧 CLI 缺少该命令时明确失败，不回退到其他执行入口。

模型等临时故障需要继续原会话时，任务先核对身份、回调与已有写入，再通过 `agents launch continue` 提供原请求和唯一续作 ID。错误分类、退避窗口、次数与备用模型配置保存在任务中；不能把上游不可用当成已评审或直接推进队列，也不重置修复额度。仍在工作、待输入或投递不确定时不重复续作，保留原 MR 与恢复记录。

## 变更与验收

模板内容变更更新包版本，同步薄适配器及嵌入资源；公共模块调整仅维护 core 的权威实现。验证清单声明文件齐全、入口可直接执行、没有私有数据。运行模块测试使用假的 Herdr／原生终端响应，覆盖继承与覆盖、参数按字面传递、会话忙碌、身份改变、超时不重发和结果恢复。普通任务不得因为统一规范被强加 Agent 依赖。

更新已安装任务必须经任务管理 API 和当前修订，不直接覆盖包目录；保留 ID、项目绑定、日程、启停状态及用户修改。旧的原生 Hermes 任务与外部系统任务继续兼容读取；只有明确更新模板或迁移才改变执行路线。

## 多套提示词

Agent 任务可保存最多 12 套命名提示词，始终只选中一套。编辑器采用左侧方案列表、右侧共用名称与正文编辑区：点击名称仅切换编辑对象，点击单选改变当前使用项；新增方案从空白正文开始，保留原使用项。全部修改随“保存任务”一起生效，取消编辑不写入；详情页只读展示当前生效正文；有多套方案时，在标题栏展示所有方案名称并用勾选标记当前使用项，不提供切换或编辑操作。方案管理和切换统一在编辑页面完成，保存失败时保留编辑草稿与原有生效内容，运行中不允许切换。

现有任务无需迁移：原有正文显示为默认方案。首次新增或命名方案时创建 `config/prompt-variants.json`，格式版本为 1；`active_id` 指向唯一方案，各方案包含稳定 `id` 和 `name`。当前方案不包含 `content` 字段，正文仍保存在原有 `prompts/prompt.md`（旧任务保留既有 `prompt.md` 路径）；其他方案在 `content` 中保存正文。原生 Hermes 使用任务 `content` 作为当前正文。切换时将当前正文存回原方案，再将目标正文写入既有运行入口，因此原有脚本继续只读取一份提示词。

方案配置属于任务定义，随复制、导出、备份和恢复一起保留，不进入 `.local/` 或业务累计记录。后端拒绝重复标识、无效选择、空正文及当前正文的重复副本。任务文件合计最多 1 MiB、64 个；每套提示词和普通正文文件最多 64 KiB，方案配置允许占用任务总预算。JSON 导入、更新恢复记录与旧格式备份使用独立的 8 MiB 编码上限，避免 JSON 转义使合法正文无法读回。

每套方案还可以声明一个可选的 `behavior` 行为标识，作为任务脚本读取的元数据。AgentHub 不解释该值，也不会因为设置它改变权限或执行动作；未设置时保持旧格式和旧运行行为。CLI 与桌面端都保留该字段，任务脚本可以在单次运行时据此选择相应方案或执行分支。

`config/agent.json` 只允许 `runner`、`launch`、`execution` 三个对象。配置校验在创建会话前执行，未知字段、非法参数或越界等待期限都会直接拒绝本轮任务。

## 方案自定义变量

提示词方案的“高级设置”保留行为标识，并支持按需添加、编辑和移除自定义变量。每个方案独立保存变量，切换执行方案时使用其对应值，查看或编辑另一个方案不会改变当前执行项。不设置变量条目数量上限，内容仍受任务包整体体积保护。变量名以字母或下划线开头，仅包含字母、数字和下划线，且在同一方案内唯一；值为字符串，未配置变量的任务保持兼容。

变量保存在 `config/prompt-variants.json` 对应方案的可选 `variables` 数组，每项为 `{"name":"batch_limit","value":"10"}`。界面、CLI、导出和备份共用这份数据，不另建第二份配置。原生 Shell/PowerShell 和 Hermes 脚本通过 `AGENT_HUB_VARIABLES_JSON` 接收当前方案的 JSON 对象；Agent 执行器在提示词中附加同一方案的变量数据。变量按字面值传递，不做 Shell 展开，不自动决定业务行为；任务根据自己的行为标识和变量执行。

CLI 使用 `automations variables list <任务ID> [--variant <方案ID>]` 查看当前或指定方案；`variables set <任务ID> --name batch_limit --value 10 --revision <当前修订>` 设置，`variables unset <任务ID> --name batch_limit --revision <当前修订>` 移除。写操作可加 `--variant`，省略时修改当前方案；必须传入读回的修订号，冲突时先重读比较。操作保留其他变量、方案正文、行为标识、选中项及日程，不触发任务。

## 自定义操作

自定义操作是可选的平台扩展，默认无配置、不显示按钮。编辑任务的“自定义操作”中按需添加；任务详情页在常规操作旁展示，超过两个操作收进“更多操作”。保存、导入和查看任务不执行脚本。

`config/actions.json` 使用 `version: 1` 与 `actions` 数组，最多 12 项。每项包含唯一 `id`、`name`、`script`，可选 `description`、`arguments`、`confirmation`、`preview_arguments`。脚本必须是任务已声明的 `.sh`、`.ps1` 或 `.py` 文件；参数以独立 argv 传入。未配置确认与预览时点击直接执行，填写确认文案时先确认。

配置 `preview_arguments` 后先以这些参数执行同一脚本，脚本负责只读检查并输出 JSON：

```json
{
  "summary": "将重置两项计数",
  "items": [{ "label": "处理次数", "current": "3", "after": "0" }],
  "preserved": ["执行历史保留"],
  "token": "opaque-state-revision"
}
```

平台统一展示当前值、执行后值和保留项。用户确认后，以 `arguments` 执行，预览令牌通过 `AGENT_HUB_ACTION_PREVIEW_TOKEN` 交还任务脚本；脚本必须在自己的状态事务中核对令牌，状态已变时拒绝执行并要求重新预览。平台不猜测业务计数、不清空业务状态。

执行以当前用户身份进行，沿用任务项目目录、`AGENT_HUB_TASK_DIR`、`AGENT_HUB_SCRIPT_DIR`、`AGENT_HUB_STATE_DIR`、`AGENT_HUB_VARIABLES_JSON`，并提供 `AGENT_HUB_ACTION_ID` 和 CLI 入口。操作最长 60 秒，不适合常驻任务；失败或结果未明不自动重试。定义修订变化、正在执行或 Agent 检查点未收齐时拒绝执行。操作使用任务互斥并将结果写入本机 `.local/runs/`，不改日程、不自动触发任务、不删除历史；业务脚本仍需使用原任务锁核验子执行者和未决写入。

CLI 使用 `automations action <任务ID> <操作ID> --revision <修订>`；配置预览时先加 `--preview`，确认后通过 `--token <预览令牌>` 执行。旧任务需显式添加操作，不自动推断或迁移私有计数。

# 本地 Skills 管理

## 项目安装与团队共用

普通项目以 `.agents/skills` 作为项目级中央技能仓库。添加 Skill 时，先准备或复用这里的实际内容，再按所选 Agent 的原生目录生成相对链接入口；无法创建软链接时回退复制，也可在窗口中显式选择保存副本。桌面添加窗口从本机已安装且已启用的 Agent 中选择团队目标；项目页的 Agent 筛选则只展示实际检测到安装的工具。全局部署和链接工作空间保持原有规则，设置中的链接工作空间同步模式不控制普通项目副本。

将项目中央技能内容和团队所需 Agent 的原生入口一起提交 Git，成员拉取后由 Agent 直接读取，无需个人技能库、AgentHub 或访问安装来源。团队成员可用普通编辑器和 Git 维护技能，不强制安装管理工具。项目内 `.agents/skills` 是团队版本的权威内容；相对链接直接使用中央内容，修改中央内容即可生效；复制入口仍需刷新副本。安装会复用已有项目版本，不会用个人库版本覆盖项目修改。

`.agent-hub/project-skills.json` 是可选共享的 AgentHub 管理清单，用于来源记录、内容指纹和部署关系；它不是 Agent 读取技能的入口。不提交清单不影响技能使用，维护者本机仍可保留它；其他 AgentHub 维护者缺少清单时按普通项目文件查看和手动维护，不能恢复来源关系或自动执行托管副本刷新。需要共同使用 AgentHub 管理时再一并提交清单。

项目页将“技能与 Agent 入口”和“AgentHub 管理清单（可选共享）”分开，支持复制技能路径。检查包含技能内部资源：被忽略的整个目录只提示一次，单独被忽略的文件仍提示；已经纳入 Git 跟踪的文件不会被误报。只有管理清单被忽略时不显示技能共享警告。调整忽略规则时只放行团队技能路径，保留其他个人配置的忽略规则；如果父目录被整体忽略，也需允许 Git 遍历这些父目录。应用不会自动提交、推送或修改忽略规则；安装成功不等于其他成员已经收到文件。

部署流程：项目页“添加技能” → 从个人技能库选择技能 → 选择 Agent 与入口模式 → 准备或复用项目中央版本 → 一次生成原生入口 → 返回项目页审查共享路径与 Git 差异 → 提交。窗口显示目标项目，默认选中可用的已启用 Agent，历史选择只保留仍可用的目标；没有已启用 Agent 时先到设置中启用。全部成功后关闭窗口，部分失败时保留失败项以便重试，已成功项不会重复部署。链接工作空间沿用独立语义，不提示团队 Git 共享。

个人库更新不自动改变团队版本。显式更新项目时检查项目和全部团队副本的基线，拒绝覆盖本地修改；修改项目库后可刷新已有团队副本。没有实际入口的 Agent 属于未添加状态，不提示缺失，也不会通过恢复操作自动添加；需要使用时由用户点击 Agent 图标或显式部署添加。修复不下载来源、不升级版本。专属入口可单独启停，公共目录启停影响直接读取该目录的宿主；个人 Agent 设置不会改写项目文件。

CLI 示例：

```sh
agent-hub-cli --json project --path ~/projects/demo status
agent-hub-cli project --path ~/projects/demo add code-review --agent claude_code --agent codex
agent-hub-cli project --path ~/projects/demo add code-review --agent claude_code --copy
agent-hub-cli project --path ~/projects/demo deploy code-review --agent cursor
agent-hub-cli project --path ~/projects/demo repair code-review
agent-hub-cli project --path ~/projects/demo update code-review code-review
```

`add` 和 `update` 的来源引用对应个人技能库；`status`、`deploy`、`repair`、项目启停和移除操作不要求个人库。复制副本是生成内容，修改后需先审查差异，不能直接重建覆盖。多文件发布失败时保留可恢复状态，下一次项目写操作先恢复；检测到外部编辑时停止恢复并保留原件。

当前仍使用可选的 AgentHub 管理清单，不写或改写已有 `skills-lock.json`；外部 CLI 锁文件完整互操作、来源固定修订下载恢复和旧项目批量迁移仍在后续规划。显式安装时，可将指向当前选中技能源的中央个人链接转换为项目实际内容，不写入或删除个人来源；其他来源链接和链接祖先仍拒绝接管。团队环境不能正确 checkout 软链接时使用复制模式。跨平台回归验证换行和空目录的 Git 可移植性；Windows 和 Linux 的宿主加载行为仍需原生环境验收。

## 入口与操作

1. 点击仪表盘的“已启用 Agent”卡片进入设置中的 Agent 管理区；从仪表盘或命令面板打开“本地 Skills 管理”，也可进入“安装 Skills → 本地”。
2. 首次进入扫描本机 Agent Skills 目录；技能库 `~/.agent-hub/skills` 中存在的 Skill 优先展示该位置，没有时展示其他来源。点击”重新扫描”更新结果。
3. 按 Skill 名称、路径或 Agent 搜索；同一路径只展示一次，目录下直接列出适用 Agent 标签，不折叠 Agent。
4. 每个目录支持“查看内容”和“打开目录”，软链接带指示图标并显示解析后的真实路径。同一 Skill 的其他来源目录默认折叠；同名不同内容分别展示。
5. 点击位置旁的删除按钮，核对确认框中的路径后删除。取消不会操作文件。删除成功后立即关闭弹窗，后台继续刷新列表；删除失败时保留弹窗并允许重试。
6. 保留单项导入及“导入全部扫描结果”。全部导入覆盖扫描结果，不受当前搜索或筛选限制。

摘要同时显示逻辑 Skill 数和按完整路径去重后的目录数；共享目录与其他 Agent 目录中同名且内容相同的 Skill 只计一个 Skill；同名不同内容仍分别计数。

## 删除边界

后端使用扫描记录定位目录，校验 Agent 根目录、路径边界、扫描时指纹和当前部署归属。内容在扫描后发生变化时，需重新扫描再删除。托管部署从 Agent 工作空间移除；技能库不能通过本地扫描删除。

删除软链接只移除链接；其他独立副本保留。删除共享目录会影响所有读取同一路径的 Agent。已导入内容的来源引用会转向保留的技能库副本，避免之后检查更新时来源丢失。

## 扫描性能验证

单次扫描按规范路径复用完整内容指纹，但仍保留每个 Agent 来源；缓存不跨扫描复用，之后的修改会重新读取。不会排除依赖目录来换取速度。Apple/Linux ARM64 启用 sha2 的硬件检测，缺少相应 CPU 指令时回退软件实现；开发构建对 sha2 单独优化，应用代码保留调试能力。

可重复运行：

```sh
cargo test --manifest-path src-tauri/Cargo.toml scan_timing_workload -- --ignored --nocapture
```

2026-10-07 在 Apple Silicon 的开发测试构建中测量：16 个 Skill、每个含 64 个 8 KiB 文件，8 个 Agent 共用根目录时从 3111 ms 降至 70 ms；单 Agent 样本从 439 ms 降至 49 ms。本机目录扫描基线为 127080 ms，优化后为 20801 ms，后续同一构建复测为 13550 ms。扩展发现规则后，位置数从 3172 增至 3376，并未通过减少扫描结果取得加速。

这些数字仅覆盖扫描器，不含 UI 渲染和数据库入库；是同机先后测量，文件缓存和后台负载会影响耗时，不是跨平台性能承诺。浏览器交互验证使用隔离 IPC fixture，不删除真实安装；文件删除和指纹保护由临时目录上的 Rust 测试验证。

## 删除弹窗回归

启动本地 Vite 服务后运行 `browser-use < tests/browser/local-skill-delete.py`。fixture 使用受控 IPC Promise 挂起删除和扫描，验证删除成功后不等待刷新、刷新失败不重新打开弹窗，以及删除失败可重试；不会调用真实文件删除。

## 有效 Agent 的检测

“已启用 Agent”只统计本机检测到安装程序且启用的 Agent。后端检查 PATH 和常见用户程序目录中的可执行文件、已安装桌面应用，以及宿主已安装的 IDE 扩展（扩展需具备匹配的 publisher/name 和入口文件，排除卸载标记）。配置文件、历史、Skills 目录和手动配置的路径都不算安装证据。

检测不启动 Agent，也不表示其正在运行或已登录。手动配置的自定义部署目标仍可由明确的部署操作使用，但不增加已安装统计；遗留 Skills 保留只读扫描与管理能力。

## 按 Agent 一键清理

1. 在“本地 Skills 管理”点击“一键清理”。后端自动预览本机 Agent 的 Skill 位置及空 Skills 目录，已安装 Agent 也会纳入清理候选。
2. 选择“按 Agent 清理”中的某个 Agent，或选择“全部 Agent”；检查列出的实际路径和数量。
3. 点击“确认清理”。取消不会删除文件。执行前重新检查安装状态、路径、内容指纹和托管部署；手动配置路径、链接根、额外共享发现目录及技能库不参与清理。同一路径保留各 Agent 的预览入口，批量清理时实际只删除一次。
4. 清理完成后弹窗立即关闭，后台刷新。成功删除后移除空 Skills 目录，保留 Agent 的其他配置与历史；软链接只移除链接。失败或已变化的位置保留并列出原因。

不会在启动时静默删除内容。浏览器回归：`browser-use < tests/browser/local-skill-cleanup.py`，验证预览、取消、按 Agent 选择、仅提交所选位置、刷新期间关闭及空结果提示，使用模拟 IPC；Rust 临时目录测试验证真实文件行为。

CLI 同样支持：`agent-hub-cli skills cleanup` 先执行一次本地扫描并输出预览；追加 `--yes` 执行删除，追加 `--uninstalled-only` 只处理未检测到安装的 Agent。支持全局 `--json` 输出机器可读结果。

从 skills.sh 安装已有本地同名 Skill 时，应用会比较内容指纹并复用原技能库目录，更新其 skills.sh 来源和版本信息，不会再生成带 `-2` 后缀的重复条目。

## 默认目录升级

默认技能目录为 `~/.agent-hub/skills/`，数据库为 `~/.agent-hub/agent-hub.db`，配置、日志仍在 `~/.agent-hub`。设置分别显示实际技能目录和应用数据目录。已有自定义库及 CLI 显式目录保持兼容。通过按 Agent 部署让工具使用选中的技能，不再提供整库共享链接开关。升级保留已有 `~/.agents/skills` 链接；如果它指向技能库，读取该路径的工具仍可看到全部技能，需手动解除链接后才能恢复按技能部署的边界。

技能库中有效的 Skills 在启动时原地登记，不复制一份。直接读取技能目录的 Agent 可以看到目录内全部 Skills；取消一条部署记录不会删除源文件，也不代表已对这些 Agent 禁用。按 Agent 的独立关闭能力仍取决于宿主规则。

## GitHub 备份与恢复

Git 工作目录跟随实际技能根，默认在 `~/.agent-hub/skills`。备份保存技能内容、Git 历史以及库内 `.agent-hub/` 的可恢复元数据；这个元数据子目录与主目录下的应用状态目录 `~/.agent-hub` 不同。应用数据库、配置、日志、缓存、迁移标记和安装器锁文件不纳入新备份提交。已在旧提交中的数据不会被改写历史删除。

从远端克隆或重新克隆时，先下载到临时目录；失败不动现有库。成功后保留整个旧库和 Git 历史，默认恢复副本位于 `~/.agent-hub/recovery/skills-<id>`，自定义库位于同级 `.agent-hub-recovery`。远端同名条目作为恢复后的版本，本地原版保留在恢复副本；仅本地存在的顶层条目（含软链接）带入新库。恢复副本不会自动清理。

历史快照恢复仍先创建安全快照，再切换库内容。软链接按 Git 的链接语义保存，不包含链接指向的外部目录内容。验证采用临时目录与本地 Git 远端，不操作真实技能或 GitHub 仓库。

首页入口回归：`browser-use < tests/browser/dashboard-agents.py`，使用真实首页与设置组件验证鼠标、Tab/Enter 导航、Agent 区域聚焦及统计。清理 fixture 的 Agent 下拉框使用原生 change 事件，避免后台浏览器依赖系统选择器；确认与取消仍通过 CDP 点击。

## 差异比较

从技能库进入详情时，左侧显示中心库、右侧显示导入来源；从项目进入时，左侧显示所选 Agent 的项目本地副本、右侧显示匹配的中心库。每个差异文件标明双方完整路径及技能声明版本，比较范围包含脚本和资料等整个技能目录。

项目详情显示项目同步状态，多个 Agent 副本可切换，默认优先查看项目较新副本。左右列不会因版本新旧改变位置；只有可比较的声明版本较高时才标记“较新版本”，缺失或相同版本不推断内容先后。项目入口以中心库为对比基准，显示本地相对中心的改动：绿色 + 表示本地新增，红色 - 表示本地删除。左右排版不改变增删统计与权限变更方向，页面提供对应图例。

## Git 仓库版本提示

安装页的仓库卡片、详情和覆盖确认显示仓库声明版本及已安装中心版本。仓库版本低于已安装版本时显示「仓库版本较旧」，禁止用旧仓库覆盖技能库，并在详情提供「同步新版到仓库」。选择本地仓库后，预览双方版本、目标目录和将移除的文件，确认后替换该技能目录；Git 元数据、仓库其他文件及中心记录与部署关系保留，不自动提交或推送。远程仓库先添加本地工作区再同步。确认后内容变化时需重新预览；同步后重新扫描并更新已打开的详情。仓库有较新版本时显示对应提示。比较采用 SemVer，未声明或无法比较的版本不推断先后。旧目录缓存自动补读一次版本，失败可手动刷新；覆盖前版本变化需要重新查看提示并确认。

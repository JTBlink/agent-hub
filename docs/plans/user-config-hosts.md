# 用户配置库与 Hosts 方案管理

状态：用户已选定 A「方案列表＋编辑器」（2026-11-03），正式实现已完成，交付验证见关联 Issue。用户已确定：每套方案保存完整 Hosts，同一时间应用一套；接入现有 GitHub 备份仓库，沿用自动备份配置；用户配置采用独立目录，为后续其他配置类型留出位置。

## 配置目录与统一备份

建议以 `~/.agent-hub/user-config/` 为用户配置库，按配置类型分目录；首个分类为 `hosts/`。每套方案平铺保存为 `hosts/<方案 ID>.hosts` 与同名 `.json` 元数据，不再为每套方案创建目录；旧 `hosts/<方案 ID>/` 和 `hosts/profiles/<方案 ID>/` 布局首次读取时自动迁移，保留方案 ID、内容与修订。配对文件写入与删除使用可恢复事务，迁移或恢复冲突时保留原文。备份仓库增加对应的 `user-config/`，与现有 `skills/`、`automations/` 并列，复用已有自动备份、提交、推送和恢复流程。

配置正文以文件为权威来源，便于外部编辑和 Git 对比。方案使用稳定标识，重命名不改变身份；后续新增类型只扩展自己的目录、校验和应用适配器。系统路径、当前应用记录及检测缓存等设备状态保存在本机。凭据沿用现有专用存储，不纳入 Git。

备份统一由 AgentHub 现有 GitHub 备份能力负责。Hosts 页面不再提供单独的“立即备份”、备份历史、Git 状态面板或重试弹窗，也不另建仓库、定时任务和备份配置。保存方案、应用以及检测到外部文件修改后，沿用已有自动备份调度；失败反馈和重试、版本查看与恢复统一进入现有“同步与备份”流程。

从 GitHub 恢复只恢复配置库，修改系统文件仍需用户显式应用。系统写入继续复用现有写入前保护与冲突检查，不为该保护另外设计管理界面。

## Hosts 页面与操作

- 展示“当前环境”：读取本机实际 Hosts，显示真实路径及当前生效方案；外部修改导致不匹配时标记“外部修改”。
- 支持在页面内直接编辑当前系统 Hosts，并用“保存到系统”明确表达实际写入；提供刷新及“另存为方案”。
- 左侧方案库支持新建、复制、重命名、删除；应用操作统一放在右侧编辑器底部。每套均为完整 Hosts，应用时整体替换，不合并多套。
- 点击左侧方案，在右侧内容区直接编辑，不额外弹窗。区分“正在编辑”与“当前生效”：选择或保存方案不改变系统内容；保存方案后再点击“应用到系统”才生效。
- 当前系统内容显示真实路径，各方案显示缩短路径，悬停可查看完整绝对路径，并支持用 VS Code 打开文件所在目录；返回应用后检测外部文件修改。未保存草稿与磁盘内容冲突时保留草稿并提示，不能静默覆盖。
- 刷新、切换编辑对象或应用其他方案会影响未保存草稿时，提供明确的保存或放弃路径。
- 系统保存与方案应用复用已有内容校验、原文修订冲突检查、按需提权及写入后验证；失败保留内容，核实写入成功后再更新生效状态。

正式实现已支持方案库与统一 GitHub 备份。旧的系统相邻 `.bak` 文件继续保留，不主动扫描或批量导入；后续读取和写入生成的设备快照进入统一配置库。写入中断恢复、容量校验和修订冲突保护由 Rust core 统一处理。

## 原型与正式实现

已选定 A「方案列表＋编辑器」。三套比较原型留存在本地 `prototype/hosts-config` 分支（提交 `0ef0a4f`），在该分支运行 `npm run prototype:hosts` 可回看；正式功能不保留原型切换栏。B／C 仅作为设计来源。

正式页面复用设置导航、主题、确认弹窗与权限说明，位于 `src/components/settings/HostsSettings.tsx`；`tests/browser/settings-hosts.html` 使用实际组件与合成 IPC 数据，可用于无系统写入的浏览器验收。

系统实际内容首次读取后进入用户配置库的设备快照；系统保存或方案应用前保留原文，写入后更新当前快照。设备键保存在本机，配置库中的快照不包含系统绝对路径；跨设备恢复不会写系统文件，之后读取仍以本机实际内容为准。所有快照沿用统一 GitHub 自动备份与版本历史，不提供第二套备份界面。

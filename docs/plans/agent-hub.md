# agent-hub 后续规划与设计

状态：规划中。更新时间：2026-10-12。

本文集中维护后续目标、设计方向、分期和待决问题，不作为已实现功能说明。唯一设计基线是当前 Skills Manager 核心及工作台，不沿用旧 agent-hub 宿主或安装器方案。当前实现见[系统架构](../architecture/overview.md)；已经接受的架构替换决策见 [ADR-0008](../adr/0008-primary-application.md)。

## 目标与约束

以 Skills Manager 实现为基础继续开发 agent-hub，优先保持可运行、易修改和可发布。保留原 Logo、图标及深蓝、蓝青紫主题；默认应用目录为 `~/.agent-hub`。

前端、桌面端和 CLI 使用同一套工程与领域核心。不恢复旧双窗口宿主，也不为保留旧结构而复制逻辑。已有用户数据不自动迁入或清理，跨库导入需要明确设计。

## 设计方向

### 模块与目录

页面保留路由和组合；状态流程下沉到 hooks/context，共享展示规则放在 lib。Rust commands 保持边界清晰，扫描、安装、存储、同步等核心职责逐步拆分。遵循 ADR-0006，随具体功能改动拆分继承的大模块，避免一次重写全部核心。

### 技能管理与同步

沿用现有技能库、导入来源、Skill Group、工作空间部署和 Git 备份模型。按真实使用反馈改进选择、执行进度和错误反馈，直接扩展现有 core 与 CLI。项目技能库方案拟在现有安全校验和部署引擎上增加可预览的项目变更操作，不建立独立安装器。

固定应用配置、日志和 CLI 与可移动技能库分离；同步和合并继续使用现有元数据协议。重点验证库移动、备份恢复、冲突处理以及桌面与 CLI 的一致性。旧应用数据保留在原目录；当前不规划自动迁移。

#### 问题与目标

当前项目部署主要从个人技能库直接写入各 Agent 项目目录。复制模式会产生多个独立副本；符号链接可能指向个人技能库，团队成员拉取项目后无法使用相同路径。项目来源、修订和部署关系主要依赖本机状态，项目 copy 副本也不在全局 `skill_targets` 更新链路中。

目标是让团队通过项目 Git 仓库共享确定的 Skill 内容，同时保持桌面与 CLI 一致的导入、更新、部署和冲突保护。个人技能库继续负责个人收藏；项目技能库仅包含显式引入项目的技能，不恢复全局整库共享链接开关。

#### 全局与项目安装的差异

| 维度         | 全局安装                       | 项目安装                                   |
| ------------ | ------------------------------ | ------------------------------------------ |
| 使用者       | 当前用户，在本机多个项目中使用 | 项目团队，使用随仓库交付的版本             |
| 权威内容     | 个人技能库                     | 项目内技能库                               |
| 内容生命周期 | 由个人安装、更新和移除         | 随项目 Git 提交、评审、拉取和回滚          |
| 部署源       | 本机个人库，可使用绝对链接     | 项目内内容，不依赖个人库链接               |
| Agent 选择   | 当前用户的已安装工具及个人偏好 | 团队声明的支持目标；本机检测只用于诊断     |
| 更新影响     | 更新个人版本及托管的全局部署   | 显式更新项目版本，个人更新不得自动改写项目 |
| 换机使用     | 需要恢复个人库与部署           | 已提交的项目内容和入口可直接使用           |

项目安装的首要验收是：维护者安装并提交后，新成员只需拉取项目并使用团队支持的 Agent，无需安装 AgentHub、导入个人库或重新下载 Skill。来源清单服务后续维护，不应成为读取已有项目内容的前置条件。

Git 分发仍需维护者提交相关文件。应用应列出需提交的项目内容、来源清单和入口，提示当前是否被忽略；不能把“安装成功”描述为其他成员已经收到更新。

团队友好性修订（2026-10-12）：按 [ADR-0011](../adr/0011-optional-project-management.md)，AgentHub 管理清单可选共享，团队消费只依赖已提交技能及原生入口。界面分别列出技能交付和管理信息，避免将 `.agent-hub` 清单误认为必需运行文件。下方候选布局中的项目管理清单改为可选提交；来源互操作等未实现项仍保持规划状态。

#### 内容与目录

普通项目采用以下候选布局；已有目录先扫描、预览，不能因为采用该布局就直接接管。

```text
<project>/
├── .agents/skills/                 # 项目技能实际内容，提交 Git
├── skills-lock.json                # 可移植来源清单，提交 Git
├── .agent-hub/project-skills.json   # AgentHub 项目身份及部署意图，提交 Git
└── .claude/skills/                  # 默认提交可直接读取的复制副本
```

项目技能库是团队实际使用版本的权威来源。个人库或远程来源到项目库采用复制；项目库到 Agent 原生目录采用直接读取、项目内链接或复制。项目可以直接创建和编辑自有 Skill，不要求先登记到个人库。

内容及可移植元数据以项目文件为准，本机 SQLite 是索引和部署执行记录，可从项目文件重建。日志、恢复原件、操作 journal、绝对路径和凭据只留在本机，不进入项目可移植元数据。项目 Git 负责团队内容版本；应用不自动 commit、push，也不借全局备份同步改变项目内容。

已提交的 Agent 复制副本属于派生内容，但也是团队交付的一部分。通过应用更新项目库时，必须同步刷新团队托管副本；直接编辑项目库后，应用检测副本陈旧并提供刷新及完整待提交文件清单。发布过程部分失败时明确提示尚不能作为完整团队版本提交。

候选目录不是新的任意路径配置入口。路径由现有适配器与作用域解析器统一计算。链接工作空间、独立 Agent 工作空间沿用现有语义，第一期仅为普通项目增加项目技能库。

#### 来源清单和兼容性

优先读取并保留 `skills` CLI 的 `skills-lock.json`：来源、来源类型、原始 URL、ref、Skill 子路径和 `computedHash`。未知字段保留；不把损坏或未知版本的清单当作空文件覆盖。

AgentHub 专属字段放在项目元数据中，以稳定项目 Skill ID 关联来源条目、中央相对路径及团队支持的 Agent。核心与 CLI 支持为未安装的团队 Agent 生成入口；桌面项目添加按 ADR-0012 从本机已安装且已启用的 Agent 中选择。目录名、展示名和稳定身份分开处理，重命名不丢失部署关系。来源清单按名称索引，因此第一期拒绝重复来源键；通过明确重命名解决冲突。

个人 Agent 偏好、安装状态和实际执行结果只保存在本机，不写回团队声明。扫描已有项目内容不要求必须存在上述两份清单；缺少来源信息的 Skill 可正常使用和登记，来源更新能力标记为不可用或待补充。

项目元数据保存确切 Git commit、来源内容指纹、引入后内容指纹、部署意图及 schema 版本。`ref` 用于检查后续更新，commit 用于恢复选定版本。恢复下载后验证指纹，不匹配则报告失败而非静默接受最新分支。保存新版本前，确认内容指纹算法、过滤规则与外部 CLI 的 `computedHash` 兼容；不兼容的内部指纹使用独立字段，不能冒充外部字段。

个人库导入且没有可移植来源时，标记为项目内维护，团队依靠已提交内容使用该 Skill。个人路径只能作为本机可选关联。相对路径来源也需判断是否仍位于仓库内；仓库外的相对路径不视为可移植来源。

#### Agent 部署策略

| 目标情况                             | 拟议行为                                         |
| ------------------------------------ | ------------------------------------------------ |
| 适配器支持直接读取项目公共目录       | 直接使用实际内容，不生成冗余入口                 |
| Agent 采用专属目录                   | 默认从项目技能库生成受管理复制副本，并随项目提交 |
| 团队明确选择且平台支持项目内相对链接 | 从专属目录链接到项目技能库，验证检出后可用       |
| 多 Agent 解析到同一物理目录          | 一次文件操作，保留各 Agent 可见性说明            |
| 目标已有未托管内容                   | 返回冲突，允许显式接管或保持原样                 |

项目部署默认策略为“团队共享”：直接读取公共目录优先，专属目录默认复制。复制增加仓库内容体积，但避免新成员依赖链接权限或本机初始化。项目内相对链接是团队主动选择的优化项，不复用全局 `sync_mode` 默认值。Windows junction 仅作为显式选择的本机生成入口，不能当作可移植链接提交。入口复制失败与链接降级应在逐目标结果中展示实际模式。

默认提交公共内容和团队所需的专属目录副本，不将这些副本加入忽略规则，也不提交团队不需要的入口。团队可选择提交经过目标平台验证的相对链接；若选择本机生成入口，则明确提示每个成员需要初始化，这属于可选工作流，不满足默认“拉取即可使用”的验收。忽略规则仅覆盖确切托管路径，首次预览后显式应用，不能忽略整个 Agent 配置目录。已跟踪文件不由应用自动改为忽略。Windows 检出不能正确还原链接时，修复入口需识别链接文本文件并展示替换预览，不能依据文件名直接删除。

生成副本不得成为隐含的第二权威版本。记录部署时指纹，重建前读取目标实际内容；有修改则报告冲突，提供“回传项目库”“以项目库重建”“保持现状”。回传项目库也需检查其他修改，不采用时间戳较新即覆盖的规则。

#### 可见性与启停

`.agents/skills` 同时是部分 Agent 的原生发现目录。因此写入其中的 Skill 可能对所有读取该目录的宿主可见，不能只凭某个 Agent 的数据库选中状态宣称独立隔离。

界面展示“共享目录可见”及实际共享 Agent 范围。直接读取同一目录的 Agent，第一期只提供共享范围的启停，不提供虚假的逐 Agent 开关。宿主有经过验证的隔离目录或排除机制时才提供独立控制。

任何移动已跟踪内容或移除已提交入口的启停操作都属于团队项目变更，随 Git 传播，界面需明确其影响。个人禁用 Agent 不得触发对团队目录的删除、移动或入口改写；没有宿主隔离能力时，只能标记本机管理偏好，不能声称该 Agent 已无法发现项目 Skill。

项目范围停用应保留原件：候选方案是移动到项目内非发现目录 `.agents/skills-disabled`，同步记录项目级停用状态；该目录内容可随 Git 保存，需验证适配器不会将其作为技能发现根。停用公共内容前处理所有依赖该内容的托管入口，避免产生悬空链接。目录规则和外部 CLI 对停用内容的处理需在评审中确认。

#### 操作和更新语义

1. **添加到项目**：选择个人库、远程或本地来源，选择团队支持的 Agent，预览名称、可见范围、冲突及文件变更，再将内容引入项目库并生成团队入口。结果列出需提交文件，不以本机 Agent 安装状态限制目标。
2. **部署到 Agent**：以项目库已有内容生成入口；不下载来源、不改变选定版本。
3. **检查来源更新**：比较来源新版本与引入基线；不覆盖项目内容。全局技能更新仅使关联项目出现可更新提示。
4. **更新项目版本**：同时比较引入基线、项目当前内容和来源候选内容。项目未修改时预览后更新；双方修改则返回冲突。第一期只做比较和明确选择，不自动文本合并。
5. **恢复内容**：内容缺失时按固定修订恢复并验证指纹；没有可移植来源时引导从项目 Git 恢复。
6. **刷新部署入口**：按当前项目内容修复缺失、陈旧或不可用入口，不把“修复”解释为升级来源版本。

团队维护流程为“添加或更新 → 刷新所有团队托管入口 → 查看项目 diff → 提交并评审”。成员消费流程为“clone/pull → Agent 直接读取项目文件”；使用已有内容无需访问来源。AgentHub 在 Git pull 后只重建本机索引并报告异常，不以旧本机状态覆盖仓库内容。项目版本回滚后，内容、入口和清单应一同回到该提交。

引入基线至少保存可信内容指纹。第一期通过两侧指纹判定修改，通过项目与来源 diff 展示候选；缺少基线时标为未知并要求预览，不能推断项目未修改。真正的三方合并需要保存基线内容，留待后续设计。

来源检查、项目修改和部署健康分别展示，避免混用一个“同步状态”。时间戳只作辅助展示，内容一致性以实时指纹为准。

#### 模块与安全执行

建立职责明确的项目技能管理 core 模块，桌面 commands 和 CLI 都通过同一接口执行。对外接口围绕扫描状态、预览操作和应用操作组织；预览不是永久覆盖授权，应用时必须复查文件状态。

内部复用既有适配器、扫描器、路径保护、安装复制规则、删除预览和部署引擎；全局与项目保留各自的状态生命周期。入口不再重复拼路径、删除目录和写来源信息。新模型不能把项目部署硬塞进仅按 Skill/Tool 唯一的全局目标表；索引应明确项目作用域。

项目操作按真实根目录串行化，覆盖扫描、检查和发布；若同时写个人库，复用 RepoLock 并规定唯一锁顺序。网络下载在写锁外完成，进入锁后重新读取当前状态。锁只能约束应用实例，外部进程的变化仍需指纹复查。

文件写入采用 staged、保留原件和 journal。以项目实际内容及元数据的发布为提交点，数据库随后重建；多文件发布中断由 journal 恢复，不能假定单次目录 rename 覆盖所有状态。中央内容发布成功但部分入口失败时返回“内容已更新、部署部分失败”，保留原件及可重试记录，不笼统返回成功或假称全部回滚。

普通替换与删除检查目标归属、部署指纹和当前类型；应用旧记录不构成任意覆盖授权。预览被外部编辑改变时停止受影响操作并重新预览。删除项目记录、卸载入口和删除项目实际内容必须是不同意图；关闭 Agent 不删除唯一项目内容。

#### 已有项目迁移

迁移为用户显式操作，不在启动或扫描时自动执行。

- 扫描公共目录、Agent 原生目录及停用目录，识别同内容副本、分歧副本、链接和未托管目录。
- 内容一致的条目可归并；同名不同内容逐项处理，未选择的版本保留。
- 指向个人中央库的链接先读取实际内容并复制到 staged，发布成功后才重建入口。
- 缺失来源或悬空链接列为不可恢复项，不生成空 Skill。
- 已有 `.agents/skills` 可能已有团队自有内容，原地登记优先，不清空目录、不强制改名。
- 提供迁移前后路径与 Git 变更预览，保存可恢复原件；中断后可恢复或继续执行。

该方案改变了既有项目“各 Agent 副本”和停用目录的语义。实施前需增加项目技能库 ADR，并明确与 ADR-0009、已有项目启停规格的关系；草案阶段不修改已接受决策或将新语义写成当前实现。

#### 实施分期

| 阶段               | 范围                                                                                 | 完成依据                                                              |
| ------------------ | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| P0：现有安全问题   | 覆盖安装保留身份及关联；删除前路径校验；逐目标错误可见                               | 同路径来源、关联保留、部分失败回归通过                                |
| P1：团队交付闭环   | 普通项目导入、可移植清单、公共目录直接读取、专属目录默认提交副本、桌面/CLI 共用 core | 新成员无 AgentHub 和个人库也能使用；本机未安装的团队 Agent 可生成入口 |
| P2：更新与恢复     | 固定修订、来源检查、本地修改保护、入口修复、journal 恢复                             | 来源和项目双方修改不丢数据；离线修复入口                              |
| P3：迁移与可选入口 | 旧副本/个人链接迁移、共享启停、相对链接及本机生成工作流                              | 迁移可重试；可选链接经目标平台验证                                    |

阶段存在依赖，P0 的全局缺陷与 P1 的项目库功能分别跟踪。范围确认后拆分 GitHub Issues 及 blocking edges，当前不领取实现任务。

团队共用的最低交付覆盖 P1，以及 P2 中更新时保护修改、刷新所有团队副本和文件中断恢复的必要部分。默认复制路径的跨平台验收属于最低交付；固定修订下载恢复和可选链接可后续扩展，不能将团队基本可用性推迟到 P3。

#### 验收与测试

优先通过项目技能管理 core 的公共行为验证，沿用现有临时目录、SQLite 和本地 Git fixture，不操作真实个人技能库。

- 维护者提交项目文件后，新成员 clone 到全新目录，无 AgentHub、本机数据库、个人库和网络访问，仅用团队支持的 Agent 即可读取已提交 Skill；至少覆盖公共目录直接读取和专属目录副本两类目标。
- 维护者本机未安装某个团队目标 Agent，仍可生成并提交其入口；个人禁用 Agent 不改变团队项目文件。
- Git pull 和项目回滚后公共内容与团队副本一致；缺少来源清单不阻止读取已有项目内容。
- 安装结果显示公共内容或团队入口被 Git 忽略、入口部分失败及待提交文件，不将本机安装成功误报为团队同步完成。
- 项目移动、Git worktree 换路径后，相对链接有效，绝对 junction 可识别并修复。
- 项目未修改且来源更新时，只更新所选 Skill；其他技能及关联保持完整。
- 项目或部署副本有修改时，常规更新、重建和取消部署不能静默销毁这些修改。
- 固定修订恢复验证内容指纹；ref 前移不改变恢复版本。
- 来源丢失、权限失败、数据库失败和阶段间进程中断均返回可观察状态，原内容可恢复。
- 共享物理目录只执行一次写入；取消一个入口不破坏其他仍在使用的入口。
- Git pull 后索引可重建，不以本机缓存反向覆盖项目清单；损坏清单和未知版本停止写入。
- 未托管内容、嵌套路径、源目标重叠、链接逃逸和预览后修改均有拒绝覆盖的行为测试。
- 三语界面区分来源更新、项目修改和入口健康，展示真实共享可见范围及逐目标失败。

实现时运行相关前端检查、Rust 测试、格式及 Clippy；平台链接行为需原生系统验证，不能只以单平台单元测试代替。

#### 待评审项与非目标

已确认方向：项目安装服务团队共用；项目 Git 分发实际内容；公共目录直接读取，专属目录默认提交复制副本；个人库和本机 Agent 偏好不改变团队版本。

待评审：来源清单与项目元数据的双文件布局、停用内容目录、可选链接的目标平台范围，以及第一期是否必须支持外部 `skills` CLI 写回后的完整互操作。前述兼容字段是目标，尚未承诺格式完全兼容。

第一期不包含自动三方合并、自动提交或推送项目、团队权限与审批系统、新建远程技能注册中心、全局整库共享链接，以及对不支持隔离的 Agent 强行实现独立禁用。

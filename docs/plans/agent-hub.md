# agent-hub 后续规划与设计

状态：规划中。更新时间：2026-10-04。

本文集中维护后续目标、设计方向、分期和待决问题，不作为已实现功能说明。当前实现见[系统架构](../architecture/overview.md)；已经接受的架构替换决策见 [ADR-0008](../adr/0008-primary-application.md)。

## 目标与约束

以 Skills Manager 实现为基础继续开发 agent-hub，优先保持可运行、易修改和可发布。保留原 Logo、图标及深蓝、蓝青紫主题；默认应用目录为 `~/.agent-hub`。

前端、桌面端和 CLI 使用同一套工程与领域核心。不恢复旧双窗口宿主，也不为保留旧结构而复制逻辑。已有用户数据不自动迁入或清理，跨库导入需要明确设计。

## 设计方向

### 模块与目录

页面保留路由和组合；状态流程下沉到 hooks/context，共享展示规则放在 lib。Rust commands 保持边界清晰，扫描、安装、存储、同步等核心职责逐步拆分。遵循 ADR-0006，随具体功能改动拆分继承的大模块，避免一次重写全部核心。

### 安装交互

保留旧安装规划中的有效需求作为后续体验核对项：区分发现、导入和部署；支持本地目录中多个 Skill 的选择；明确目标 Agent、全局或项目范围以及链接或复制模式；展示冲突和执行结果。具体交互基于现有核心重新设计，不恢复旧安装器或依赖已删除的计划对象。

### 数据与迁移

固定应用配置、日志和 CLI 与可移动技能库分离。后续导入旧数据时，先确认来源格式、内容所有权、工具目标、Preset 和认证设置的兼容边界，再定义用户可审阅的导入计划。原库保持可恢复，不用自动覆盖掩盖冲突。

### 品牌与界面

统一使用原图标和集中主题变量。保留明暗模式、系统主题、文字缩放和操作反馈；布局调整以实际桌面使用反馈为依据。

### 配置管理能力

旧配置中心已退役。是否重新引入 Agent 配置查看或编辑，需要独立需求；不能直接恢复旧架构，也不属于当前运行基线。

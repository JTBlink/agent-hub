# 自动化管理

桌面页面与 `agent-hub-cli automations` 共用 `core::automation`。原生系统任务与 Hermes 各自调度，应用不增加依赖桌面窗口存活的轮询调度器。

## 独立任务包

按 [ADR-0016](../adr/0016-independent-automation-packages.md)，新建、模板和导入统一使用独立包；下文旧 `tasks.json`、自定义脚本目录和旧 runner 的处理作为兼容路径，不用于存放新包的唯一内容。

```text
~/.agent-hub/automations/<allocated-task-name>/
├── task.json
├── scripts/                 # 包括 run.sh 或 run.ps1
├── prompt.md                # Agent 任务
├── herdr.json               # Herdr 任务
├── README.md
└── .local/
    ├── binding.json         # 本机项目绑定
    ├── receipt.json         # 安装状态、调度身份、错误和备份状态
    ├── operation.json       # 更新过程中存在的恢复 journal
    ├── env/                 # 按依赖版本组合分配的私有环境
    ├── state/
    └── runs/<run-id>/
```

显式 `AGENT_HUB_AUTOMATION_HOME` 下的包位于该根的 `workspaces/`。`package/storage` 逐包读取，正文不在清单中重复保存；`AutomationDraft.files` 和 `package_options` 是 GUI、CLI 和备份的即时快照。内容及绑定变化使 `revision` 失效。旧全局文件损坏时仍展示可读包，并报告兼容记录错误，不覆盖损坏文件。

`package/lifecycle` 编排安装、更新、卸载和删除；`registration` 提供原生与 Hermes 适配。依赖、权限安装、交换格式和迁移各有独立模块。任务锁位于系统应用数据目录的 `operations/<uuid>/`，在包删除前后保持相同身份；新包操作不持有全局长锁。运行入口通过 `.local/run.claim` 领取并检查 `ready`，卸载先撤掉 `ready` 再检查运行领取。

创建自动完成普通安装；导入先预览并生成新 ID，默认未安装。安装准备私有 Python 环境、检查外部命令并注册暂停调度，持久回执后才启用。Python 依赖使用确定版本及按版本组合隔离的环境，不修改全局安装。安装失败保留回执供重试或卸载；卸载保留正文、项目和历史，撤销调度及任务拥有的资源。网络重置通过系统管理员授权安装 UUID 独立的权限入口；不执行导入包中的任意安装钩子，也不认领旧的无回执权限资源。

删除默认保留包文件并标记不再管理；选择清理本地数据时复查项目和其他任务引用，末尾清理及备份删除意图保存在内部 `deletions/` journal。更新通过 `.local/operation.json` 保留旧内容和回执，进程中断后可恢复。显式 `migrate` 保留原任务 ID 和日程，原脚本和项目保留；切换失败回滚并可重试。

导出为包含声明正文及依赖的单个 JSON，去掉实例身份、本机绑定和 `.local`。导入支持 JSON、包目录及其清单，只读取声明文件；GUI 提交预览对象，避免预览后源文件变化。备份恢复同样默认未安装。用法及格式见[任务包说明](../product/automation-packages.md)。

Hermes 包的 `hermes.script` / `hermes.monitor_script` 指向已声明的 `scripts/` 文件；适配器核实 CLI 能力，在 `<profile>/scripts/agent-hub-<uuid>/` 创建实际桥接文件并保存回执。创建使用位置参数，先用远期间隔日程获取 ID 并暂停，再编辑为真实日程。结果不明时禁止重复创建，明确提示核对并卸载重试。Hermes 自己的集中定义及运行历史仍由其管理。

## 兼容路径与原有模块

| 模块                                                           | 职责                                                                |
| -------------------------------------------------------------- | ------------------------------------------------------------------- |
| `definition.rs`                                                | 跨端输入、日程、创建记录与输入校验                                  |
| `workspace.rs`                                                 | 脚本目录分配、旧目录兼容与归属记录；执行工作区独立保存              |
| `store.rs`                                                     | 原子 JSON 写入、进程间操作锁与版本校验                              |
| `managed.rs`                                                   | 创建、乐观并发编辑、删除、手动运行、创建记录关联                    |
| `native.rs`、`native/render.rs`                                | 当前用户的 launchd / systemd / Windows 注册与触发，生成独立执行脚本 |
| `hermes_manage.rs`                                             | 固定参数调用已安装 Hermes CLI，按任务文件定位 profile               |
| `launchd.rs`、`linux.rs`、`windows.rs`、`cron.rs`、`hermes.rs` | 原有任务读取；来源独立报告失败                                      |

`native/shell_entry.rs` 统一短名入口分配与命令包装。系统任务定义中的 `content` 保存 `sh './run.sh'`（Windows 为 `& './run.ps1'`），入口正文与 Python 脚本一起存入 `files`；普通内联命令保存时转为入口正文。共用目录时按文件占用分配 `run-2.sh` 等名称，持久定义与文件头共同确认归属，不按名称认领文件。原生运行包装器直接调用该 Shell 入口，负责记录日志与退出码；定时和手动运行复用同一路径。空闲旧任务在保存定义与刷新包装器成功后，将同内容的长名脚本归档到内部 `previous-command.sh`；任一步失败保留原文件，定义提交失败恢复旧包装器。

模板入口通过 `AGENT_HUB_SCRIPT_DIR` 以绝对路径定位脚本；项目切换只改变执行目录。旧模板中生成的单行 Python 启动命令在显式保存时转换，用户自定义的多行脚本保持原样。

## 创建者与调度器

`source` 表示调度器，`origin` 表示创建者，二者独立。`origin=agent_hub` 必须有创建记录，按调度器、原始标识和确切配置位置匹配；同名 LaunchAgent / LaunchDaemon 不能合并，名称或 Bundle ID 不能用于声称归属。

记录位于系统本地应用数据目录的 `com.jtstudio.agenthub/automations/tasks.json`，与技能库搬迁、备份和 SQLite 无关。macOS 使用 `~/Library/Application Support/`，Linux 通常使用 `~/.local/share/`（遵守 XDG），Windows 使用 `%LOCALAPPDATA%`。独立位置避免技能库根目录整体搬迁后原生调度器找不到执行脚本。`AGENT_HUB_AUTOMATION_HOME` 支持显式隔离的绝对目录，GUI 和 CLI 使用相同约定。读取缺失文件不创建记录；损坏记录报告错误并保留外部任务，不能静默覆盖。

原生任务使用 UUID 标识，修改前重新计算并核对当前用户的目标标识、配置路径。写入持有独立进程锁；更新需匹配 `revision`，注册或记录提交失败尝试恢复旧配置，恢复失败明确返回。可编辑的外部 launchd 定时任务保持原始归属与配置路径，不接管为 AgentHub 任务。

## 执行与限制

- macOS 使用当前 GUI 用户的 LaunchAgent；Linux 使用用户级 service/timer；Windows 使用当前 SID 的 InteractiveToken / LeastPrivilege 任务。无需管理员提权。执行依赖登录会话，Linux linger 可由用户另行配置。
- 新建和保存不设置开机立即运行；计划日程仍可在下一次匹配时间执行。仅手动任务无计划触发器。暂停原生任务只撤掉计划触发能力，保留手动运行能力。
- 手动运行使用 `launchctl kickstart`（不带强制重启）、`systemctl --user start --no-block` 或 `schtasks /Run`，不更改日程定义。系统调度器负责同一任务实例的串行执行，运行期间可以打开编辑并修改草稿；保存时重新核对，仍在运行则保留输入并提示等待。正在运行时拒绝应用修改、删除与再次触发。
- 原生命令使用 `/bin/sh` 或 PowerShell，以当前用户身份执行；`script_dir` 保存脚本与提示词，`workdir` 为执行时当前目录。项目工作区选择器复用已关联项目，选中后自动切到项目目录执行，不向项目写入任务脚本。脚本目录留空时，自动创建 `~/.agent-hub/automations/<任务名称>/` 并保存实际路径；名称复用路径安全清洗，已占用的名称添加 `-2`、`-3` 等后缀，不认领已有目录。任务 ID 与目录名称的关联保存在内部任务目录的 `workspace-name.json` 中，重复分配和修改任务名称沿用已分配路径；已分配目录丢失时要求显式修复，不另建目录掩盖数据丢失。显式脚本目录与项目目录须存在；工作目录未指定时在脚本目录执行。旧定义缺少 `script_dir` 时沿用原工作目录保存脚本，编辑保存后分开管理；旧版本 UUID 默认路径原样保留。备份识别新旧默认目录，恢复时为副本分配新目录。隔离环境变量指定时，默认脚本目录也隔离到该根的 `workspaces` 下；仅列表查询不创建目录。每次执行在任务目录 `runs/<run-id>/` 中保存开始／结束时间、退出码和输出，并保留最近 100 次；根目录 `output.log`、`started`／`exit` 继续表示最近一次状态以兼容旧版本。Unix 脚本和输出使用私有权限。删除任务始终取消调度并移除创建记录，默认保留本地数据；GUI 可勾选“同时删除本地任务数据”，CLI 对应 `--delete-local-data`，清理明确分配的自动目录（兼容旧 UUID/workspace 父目录）和内部运行记录。自定义、其他任务引用的共享目录保留，不按名称认领目录。清理前及实际删除前复核路径，拒绝根目录、链接／junction 和越界；未能完成清理时保留本地 `removal_pending` 及创建记录，重试跳过已完成的取消调度，禁止该任务再次编辑、执行或自动升级。该本地阶段不进入 Git 备份。运行包装器与记录使用系统应用数据目录，脚本默认保存在应用主目录下，执行目录可指向项目；用户自行移动目录后需在任务中更新对应路径。
- Hermes 调用 `cron create/edit/pause/resume/remove`，不重写 `jobs.json`，未选择的模型、技能等选项保留。创建从 CLI 成功响应读取真实 ID，写入创建记录后才展示 AgentHub 归属。外部 Hermes 任务编辑后仍是其他来源。
- Hermes 的 `cron run` 可能同步执行较长模型任务，因此以独立进程请求，输出写入 `hermes-runs`；执行锁和结果由 Hermes 自己维护，不套用查询超时。暂停和终态任务要求先恢复/修复。返回请求成功不能视为任务执行成功；Hermes 可能按自己的领取规则推进下一次运行时间，但不修改日程定义。
- 当前仅支持本机；不提供远程主机、跨设备接管或合成运行历史。系统任务编辑支持每日、工作日、分钟间隔与手动模式；Hermes 额外接受其自定义日程表达式。未知状态或运行时间保留未知。

## 页面

列表按创建者分组筛选，调度器和状态为独立筛选条件，系统内置过滤默认开启。新建/编辑采用左侧名称与正文、右侧调度设置；详情为可链接页面，包含面包屑、概述/执行/技术信息、标题状态、运行指标和正文，提供立即运行与编辑。技术标识不占据列表名称列，命名与图标解析继续复用已有只读适配器。

UI 和 CLI 不复制任务校验与权限判断。IPC 薄封装运行在阻塞线程池；异步错误保留表单内容与已读取的任务。前端显示 `can_edit` / `can_run` 能力，后端仍重新核对真实任务及创建记录。

编辑器统一使用“项目工作区”名称，以已关联项目的名称作为选项，所选路径直接作为执行目录，不再另设工作目录输入框。脚本目录独立显示；两处均提供 VS Code 与文件夹选择入口。选择使用系统文件夹对话框，取消保留原路径；VS Code 复用统一目录链接启动器，路径为空时禁用。两项操作均不保存或执行任务，失败保留表单并允许重试。

## 执行输出

执行输出标题右侧可复制当前记录已经加载的原始文本，保留换行；加载、无输出或输出不可用时禁用。复制操作复用共享剪贴板按钮，失败后可重试；超长输出仍遵守末尾 256 KiB 的读取边界。

详情的“执行”页签按时间倒序展示记录，点击后查看单次结果，返回时保留当前任务。系统任务的独立执行脚本在 `runs/<run-id>/` 保存 `started`、`finished`、`exit`、`output.log`，默认保留最近 100 次；应用关闭后仍能记录执行。根目录最新标记保持兼容。已有旧任务在启动时升级空闲的受管执行脚本，活跃任务在完成通知后重试升级；手动运行和保存也会使用新脚本，调度定义不因此改变。升级时保留尚未覆盖的旧版最近记录为 `legacy`，无法恢复已被覆盖的历史。

Hermes 只读其 profile 下 `cron/output/<job-id>` 中已有结果文件，沿用 Hermes 自身的保留策略，以保存时间和“已保存”展示，不把文件存在当成执行成功。外部系统任务无可读记录时明确说明。

GUI 和 CLI `automations runs <task-id>`、`automations logs <task-id> --run <run-id>` 共用只读 `history.rs`／`output.rs`。按任务归属和作用域解析记录 ID，拒绝路径穿越和越界符号链接；输出按纯文本展示，最大读取末尾 256 KiB，兼容 PowerShell UTF-16。记录清理、未知状态和读取失败有明确反馈。运行记录位于本机应用运行目录，不进入任务定义的 `pending_backup`，不投影到技能备份元数据。回归测试检查实际 Git remote 只含任务定义，没有 `runs`、日志、退出码或执行内容。

参考 Orca 的变更事件与窗口生命周期：`events.rs` 仅观察注册文件及运行开始／结束标记，合并事件后推送专用通知，GUI 在后台读取；窗口恢复焦点、重新可见和手动操作也会补查。没有定时刷新界面的轮询。日志连续写入、工作目录文件与技能库变动不触发此通知，后台更新保留已显示日志、选中记录、页签和焦点。文件监视失败时仍可手动刷新。这里只刷新展示，不承担调度。

## 验证

单元测试覆盖跨平台配置生成、引号路径、多行脚本退出码、创建者的确切作用域、损坏记录、写锁与失败恢复。`src-tauri/tests/automation_management.rs` 为显式运行的原生验收：生成唯一的用户级手动任务，创建、编辑、拒绝过期版本、手动运行、读取结果、删除并清理；不修改用户已有任务。

```bash
cargo build --manifest-path src-tauri/Cargo.toml --bin agent-hub-cli
cargo test --manifest-path src-tauri/Cargo.toml --test automation_management -- --ignored
```

## Git 自动备份与模板

磁盘清理的可选下载缓存遇到权限拒绝时保留条目，计入跳过与警告并输出路径；只有这些警告时返回 0。其他 I/O 错误、非法规则和工作目录清理错误仍返回非零退出码。该分类不改写已有执行记录，新运行读取修复后的脚本。

任务注册记录同时持久化 `pending_backup`，按任务 ID 合并配置变化与删除标记；只读查询、执行日志与手动触发不进入队列。`backup_workspace::prepare_unlocked` 在既有 RepoLock 内获取自动化锁，将待处理定义投影为技能元数据中的 `.agent-hub/automation-<UUID>.json`，写入后确认队列。此锁顺序固定为 RepoLock → 自动化锁，任务修改本身只持有自动化锁，避免死锁。

这些平铺 JSON 是现有对象合并引擎可识别的 residual blob，按独立任务合并，保留增删与快照恢复；不用会被旧合并引擎忽略的未知子树。投影只包含名称、Provider、命令/提示词、脚本内容、日程和工作目录等定义，不包含调度器标识、配置路径、图标、运行日志、进程和原生包装器。默认脚本目录回到未指定语义，主目录内的显式目录表示为 `~/...`。

文件监视器额外监视当前应用的注册目录、脚本目录及声明脚本的父目录（非递归），检测配置与 Shell／Python 脚本变化；持续使用现有自动备份开关、防抖、重试及错误提示。应用未运行时不新建后台守护进程，下次启动或手动备份处理待提交定义。

Git 内容恢复只更新同步定义，不变更运行中的本机任务。GUI 在自动化页的“更多操作 → 从备份恢复”中提供独立恢复入口，供查看后新建；CLI 的 `restore` 先预览，`--apply` 显式创建暂停副本。内置模板由 Rust core 生成，GUI 和 Agent CLI 使用同一份当前平台命令；Windows 使用 PowerShell，其他平台使用 `/bin/sh`，默认目录展示四个核心场景，macOS 额外提供网络重置模板；旧 Hermes 模板仅在已安装时通过兼容查找返回。

自动备份回归使用本地 bare remote 验证任务定义新增、更新、删除的实际推送，以及快照恢复后定义保留且本机任务不被覆盖。所有数据和目录隔离，未操作用户配置的 Git 远端。

清理模板由 Shell 入口调用预装多文件 Python 包：入口、JSON 配置、安全文件操作、明确目录规则、工具调用、中文总结与通知分开维护，说明文件一并分发。JSON／Markdown 作为任务声明文件与模块一起受路径、64 KiB／32 文件预算、所有权和自动备份约束；配置与脚本修改均触发非递归监视器同步。

默认保留 7 天的下载缓存、Agent 缓存／日志和已退出浏览器缓存；工作目录日志保留 30 天。uv 离线及 Homebrew 官方清理默认启用，保留被引用的依赖、不强制清理。项目目录只从显式配置或当前工作目录获取，不扫描主目录或所有项目；AgentHub 复用已有保留最新构建工具，其他 Rust 项目只清理过期增量缓存，编译期间跳过。普通缓存保留硬链接，显式 Rust 增量目录可以 unlink 过期硬链接，仅移除目录内的名字，其他位置内容保留；共享文件大小与实测磁盘释放量分开展示。链接／junction、越界路径、锁文件和删除前已变化的条目均保留。

更新缓存仅在应用标识一致、包版本不高于已安装版且超过保留期时清理；更新进程、pending、新版本和未知格式保留。对话、数据库、凭据、配置、技能、Downloads、安装运行时和 Playwright 浏览器不自动清理。跨平台通知通过系统工具请求，预览不删除也不通知，通知失败不影响清理退出码。CLI 支持配置、保留期、规则和通知开关；原生工具的结果不冒充已确认的文件删除统计。测试只在隔离目录执行，覆盖多文件安装／回读、配置、路径／链接边界、保留版本、预览、错误隔离和通知参数。

## Herdr Agent 模板与提示词编辑

包含 `prompt.md` 的 Agent 任务直接在主编辑区编辑提示词；该正文仍作为声明文件保存、同步与备份，界面不另外维护一份提示词状态。Shell 命令默认一行，现有多行命令保留；Agent 的启动命令和脚本收进高级执行设置。`herdr.json` 保存智能体、明确的 Herdr 会话及原生参数，右侧提供智能体与项目工作区入口。

Herdr 模板使用共用的 `herdr-agent.py`，系统调度发起后先核实目标会话已运行，再以所选项目目录创建工作区或任务标签页，使用返回的面板 ID 启动 Agent 并投递提示词，所有创建均不抢占焦点。不使用 UI 当前焦点隐式定位，不自动启动或重启 Herdr 服务，不自动回答审批。命令参数以 argv 传递。声明 JSON／Markdown 文件读取时去除 AgentHub 所有权头。

智能体选择、执行说明、额外参数与 Herdr 会话放在同一组，高级区域提供额外的智能体参数输入，原文保存在 `herdr.json` 的 `extra_arguments`，与默认 `arguments` 分开管理；启动时按命令行引号解析并追加到默认参数之后，不经 Shell 执行。切换 Agent 清空原 Agent 的额外参数，Codex 默认使用 `--dangerously-bypass-approvals-and-sandbox` 以无人值守执行。已有任务保存的自定义参数保持原样。`agent get` 等状态命令按 JSON 解析，`agent read` 的终端输出按纯文本接收；等待确认时只读取可见区域，不滚动应用历史。

本地 `.herdr-run.json` 在布局创建及提示词投递之前记录状态。上次仍在工作时直接跳过当前触发，返回成功并记录跳过原因，不排队、不新建布局、不读取历史或重复投递，保留本地状态；即使上次记录已完成，也重新核对 Agent 的当前状态。等待确认、状态不明或投递结果不确定时不重复投递；用户在 Herdr 确认后可处理该本地状态。它不属于声明文件，不进入任务定义备份。运行记录保存面板标识和可读取的终端输出；Herdr 就绪不等同于任务验证成功。

启动状态单独记录 `phase=starting` 与 `prompt_attempted=false`；提示词提交前先持久化 `prompt_attempted=true`。启动器退出但面板仍在时，只有明确未投递提示词或上一轮已完成，且前台仅有该项目的 shell 进程时才在原面板恢复；忙碌面板跳过，已尝试投递但结果不明的旧状态继续保留。Codex 任务通过单次启动参数 `-c check_for_update_on_startup=false` 关闭交互更新检查，不改全局配置；额外参数仍追加在默认参数之后。

每个任务复用固定标签页。上一轮完成后核对 Agent 名称及项目目录，在原标签页创建新面板，再次核对旧 Agent 已就绪才关闭旧面板，最后启动全新 Agent；保留侧边工具，不累积对话上下文。若旧 Agent 不存在，继续检查旧面板；只有明确 `pane_not_found` 时才自动重建任务标签页，连接失败或面板被其他进程占用不等同于用户关闭。

提示词不使用 CLI 的 5 秒活动门槛作为任务终态：只提交一次，然后在执行进程内观察状态和完成序号，直到有活动后的就绪状态或明确的新完成序号。`unknown` 保持进行中，旧版 `agent_prompt_stalled` 也只继续观察，不重发；整个等待期间原生包装器保持运行，已有开始／结束标记驱动界面状态更新。最多等待 30 分钟，超时保留会话。

内置每小时维护（:15，只读）、MR 定时处理（:30）和 Issue 自动处理（:45）模板；后两者的提示词仅授权明确候选的分支实现、验证及草稿交付，不自动合并或发布。每小时日程以固定本地分钟执行：launchd 使用仅含 Minute 的日历，systemd 使用每小时 OnCalendar，Windows 使用下一次目标分钟开始的一小时重复触发。

## 统一创建入口

新建任务使用同一套布局，始终显示单行命令与提示词区域，右侧“智能体（可选）”包含“不使用智能体”。未选择时直接执行命令、提示词区禁用；选择本机 Agent 后使用 `AutomationCatalog.agent_starter` 的通用 Herdr 启动文件，提示词留空由用户填写，不复用维护／审计任务内容。切换前后的命令和提示词在当前编辑会话中保留，名称、项目目录和日程保持共享。

选项使用 `get_tool_status` 的安装与启用状态，经共享 `orderedWorkspaceAgents` 沿用全局工作区的分类和排序；名称、图标同样复用领域记录与 AgentIcon。应用工具键集中映射到 Herdr 的 Agent kind，只展示两者支持的交集。新选的 Hermes Agent 也在 Herdr 中运行；已有 Hermes 原生定时任务保留原调度方式，编辑时不能跨调度器转换。

## 内置模板范围

默认目录保留四个核心场景：项目巡检、MR 处理、Issue 处理和清理磁盘缓存。巡检合并近期变更、失败验证与卡住工作等只读检查，不再为目录检查、Git 状态、仓库审计、代码巡检和每日摘要各列一张卡片。三个 Agent 模板的提示词控制在 160 个字符内，具体流程由目标项目规范与已安装技能提供。Shell 命令和通用 Agent 任务可直接新建，不增加空白示例模板。

已创建任务及备份仍携带完整定义，不受目录精简影响；CLI 显式使用旧模板 ID 时通过兼容查找创建。“使用模板”直接展示内置模板，不提供来源切换；“从备份恢复”独立展示已保存的自动化配置，选择后填入编辑器，保存时创建默认暂停的副本，不覆盖本机已有任务。

## 文件树与外部 launchd 管理

脚本区按目录展示文件树，默认不渲染代码编辑器，选择后仅编辑单个文件；提示词仍在主编辑区编辑。任务列表和详情按项目路径匹配已关联工作区名称，未关联目录显示末级名称，完整路径保留在悬浮提示中；搜索同时匹配名称和路径。

当前用户 `~/Library/LaunchAgents` 下可写、非链接且仅包含常见分钟间隔、每小时、每日或工作日日程的定时任务可原位置管理。保持外部来源，不迁移为 AgentHub 记录，不备份或删除原脚本。命令未修改时保留原 argv；修改时使用 `/bin/sh -c`。保留环境、日志和其他 plist 字段。文件摘要与有效禁用状态共同构成版本号，保存时检查版本；launchctl 失败恢复原文件及加载状态。运行中的任务禁止修改或删除。第三方 `/Library/LaunchAgents` 和 `/Library/LaunchDaemons` 下 root 所有且不可被其他用户写入的常见定时任务也支持原位置管理，操作通过 macOS 原生管理员授权执行；授权后重新校验文件摘要、有效禁用状态、加载路径和运行状态。删除只移除 plist，不删除脚本与日志；保存或加载失败恢复原文件和加载状态。Apple 系统任务、复杂日历及持续运行／按事件触发的服务保持只读。`RunAtLoad` 定时任务在重新加载时临时使用 false，加载结束恢复磁盘原值，避免保存、恢复及回滚时意外启动任务，同时保留下次登录的原行为。

macOS 额外提供“定时重置网络”：每天 07:00，默认暂停；脚本目录内的 setup.sh 显式通过管理员权限安装 root 所有的固定网络重置入口及无参数 sudoers 白名单，不创建其他调度、不立即断网。网络服务名与 1–60 秒时长在安装时固定，默认 Ethernet／5 秒；定时脚本通过 sudo -n 调用，未安装时给出说明。EXIT／INT／TERM 会尝试恢复网络。删除任务保留权限入口，README 提供独立卸载说明。

### 下次运行时间

Windows、systemd 和 Hermes 返回的下一次时间优先使用调度器原值。launchd 不提供下一次触发时间，因此已启用且安装/注册有效的每小时、每日和工作日日历任务，在每次查询时按本机时区计算严格晚于当前时刻的下一次日程。停用、未安装、手动任务和注册未知的任务不生成未来时间；没有可靠计时锚点的 `StartInterval` 不猜测相位。

自动化页在最近的下一次日程到点后重新查询，以滚动到下一轮，启停和保存日程仍沿用原操作完成后的刷新。读取失败按一分钟间隔重试；页面隐藏时交由已有的焦点/可见性刷新处理，卸载页面清理计时器。

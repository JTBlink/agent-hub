# 自动化管理

桌面页面与 `agent-hub-cli automations` 共用 `core::automation`。原生系统任务与 Hermes 各自调度，应用不增加依赖桌面窗口存活的轮询调度器。

| 模块                                                           | 职责                                                                   |
| -------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `definition.rs`                                                | 跨端输入、日程、创建记录与输入校验                                     |
| `workspace.rs`                                                 | 留空工作目录时按任务名称建立独立工作区，内部记录目录归属，显式路径不变 |
| `store.rs`                                                     | 原子 JSON 写入、进程间操作锁与版本校验                                 |
| `managed.rs`                                                   | 创建、乐观并发编辑、删除、手动运行、创建记录关联                       |
| `native.rs`、`native/render.rs`                                | 当前用户的 launchd / systemd / Windows 注册与触发，生成独立执行脚本    |
| `hermes_manage.rs`                                             | 固定参数调用已安装 Hermes CLI，按任务文件定位 profile                  |
| `launchd.rs`、`linux.rs`、`windows.rs`、`cron.rs`、`hermes.rs` | 原有任务读取；来源独立报告失败                                         |

`native/shell_entry.rs` 统一短名入口分配与命令包装。系统任务定义中的 `content` 保存 `sh './run.sh'`（Windows 为 `& './run.ps1'`），入口正文与 Python 脚本一起存入 `files`；普通内联命令保存时转为入口正文。共用目录时按文件占用分配 `run-2.sh` 等名称，持久定义与文件头共同确认归属，不按名称认领文件。原生运行包装器直接调用该 Shell 入口，负责记录日志与退出码；定时和手动运行复用同一路径。空闲旧任务在保存定义与刷新包装器成功后，将同内容的长名脚本归档到内部 `previous-command.sh`；任一步失败保留原文件，定义提交失败恢复旧包装器。

## 创建者与调度器

`source` 表示调度器，`origin` 表示创建者，二者独立。`origin=agent_hub` 必须有创建记录，按调度器、原始标识和确切配置位置匹配；同名 LaunchAgent / LaunchDaemon 不能合并，名称或 Bundle ID 不能用于声称归属。

记录位于系统本地应用数据目录的 `com.jtstudio.agenthub/automations/tasks.json`，与技能库搬迁、备份和 SQLite 无关。macOS 使用 `~/Library/Application Support/`，Linux 通常使用 `~/.local/share/`（遵守 XDG），Windows 使用 `%LOCALAPPDATA%`。独立位置避免技能库根目录整体搬迁后原生调度器找不到执行脚本。`AGENT_HUB_AUTOMATION_HOME` 支持显式隔离的绝对目录，GUI 和 CLI 使用相同约定。读取缺失文件不创建记录；损坏记录报告错误并保留外部任务，不能静默覆盖。

原生任务使用 UUID 标识，修改前重新计算并核对当前用户的目标标识、配置路径。写入持有独立进程锁；更新需匹配 `revision`，注册或记录提交失败尝试恢复旧配置，恢复失败明确返回。当前不提供对外部系统任务的接管或编辑功能。

## 执行与限制

- macOS 使用当前 GUI 用户的 LaunchAgent；Linux 使用用户级 service/timer；Windows 使用当前 SID 的 InteractiveToken / LeastPrivilege 任务。无需管理员提权。执行依赖登录会话，Linux linger 可由用户另行配置。
- 新建和保存不设置开机立即运行；计划日程仍可在下一次匹配时间执行。仅手动任务无计划触发器。暂停原生任务只撤掉计划触发能力，保留手动运行能力。
- 手动运行使用 `launchctl kickstart`（不带强制重启）、`systemctl --user start --no-block` 或 `schtasks /Run`，不更改日程定义。系统调度器负责同一任务实例的串行执行，运行期间可以打开编辑并修改草稿；保存时重新核对，仍在运行则保留输入并提示等待。正在运行时拒绝应用修改、删除与再次触发。
- 原生命令使用 `/bin/sh` 或 PowerShell，以当前用户身份执行；工作目录留空时，自动创建 `~/.agent-hub/automations/<任务名称>/` 并保存实际路径；名称复用路径安全清洗，已占用的名称添加 `-2`、`-3` 等后缀，不认领已有目录。任务 ID 与目录名称的关联保存在内部任务目录的 `workspace-name.json` 中，重复分配和修改任务名称沿用已分配路径；已分配目录丢失时要求显式修复，不另建目录掩盖数据丢失。显式工作目录须存在；旧版本 UUID 默认路径原样保留。备份识别新旧默认目录，恢复时为副本分配新目录。隔离环境变量指定时，默认工作目录也隔离到该根的 `workspaces` 下；仅列表查询不创建目录。每次执行在任务目录 `runs/<run-id>/` 中保存开始／结束时间、退出码和输出，并保留最近 100 次；根目录 `output.log`、`started`／`exit` 继续表示最近一次状态以兼容旧版本。Unix 脚本和输出使用私有权限。删除成功后清理原生任务脚本及执行日志，保留工作目录和其中的用户文件。任务记录与执行脚本使用系统应用数据目录，工作目录则按用户要求位于应用主目录；用户自行移动工作目录后需在任务中更新路径。
- Hermes 调用 `cron create/edit/pause/resume/remove`，不重写 `jobs.json`，未选择的模型、技能等选项保留。创建从 CLI 成功响应读取真实 ID，写入创建记录后才展示 AgentHub 归属。外部 Hermes 任务编辑后仍是其他来源。
- Hermes 的 `cron run` 可能同步执行较长模型任务，因此以独立进程请求，输出写入 `hermes-runs`；执行锁和结果由 Hermes 自己维护，不套用查询超时。暂停和终态任务要求先恢复/修复。返回请求成功不能视为任务执行成功；Hermes 可能按自己的领取规则推进下一次运行时间，但不修改日程定义。
- 当前仅支持本机；不提供远程主机、跨设备接管或合成运行历史。系统任务编辑支持每日、工作日、分钟间隔与手动模式；Hermes 额外接受其自定义日程表达式。未知状态或运行时间保留未知。

## 页面

列表按创建者分组筛选，调度器和状态为独立筛选条件，系统内置过滤默认开启。新建/编辑采用左侧名称与正文、右侧调度设置；详情为可链接页面，包含面包屑、概述/执行/技术信息、标题状态、运行指标和正文，提供立即运行与编辑。技术标识不占据列表名称列，命名与图标解析继续复用已有只读适配器。

UI 和 CLI 不复制任务校验与权限判断。IPC 薄封装运行在阻塞线程池；异步错误保留表单内容与已读取的任务。前端显示 `can_edit` / `can_run` 能力，后端仍重新核对真实任务及创建记录。

编辑器在“工作目录”标签右侧提供“在 VS Code 中打开”图标，路径输入框右侧提供文件夹选择图标。选择使用系统文件夹对话框，取消保留原路径；VS Code 复用统一目录链接启动器，路径为空时禁用。两项操作均不保存或执行任务，失败保留表单并允许重试。

## 执行输出

执行输出标题右侧可复制当前记录已经加载的原始文本，保留换行；加载、无输出或输出不可用时禁用。复制操作复用共享剪贴板按钮，失败后可重试；超长输出仍遵守末尾 256 KiB 的读取边界。

详情的“执行”页签按时间倒序展示记录，点击后查看单次结果，返回时保留当前任务。系统任务的独立执行脚本在 `runs/<run-id>/` 保存 `started`、`finished`、`exit`、`output.log`，默认保留最近 100 次；应用关闭后仍能记录执行。根目录最新标记保持兼容。已有旧任务在启动时升级空闲的受管执行脚本，活跃任务在完成通知后重试升级；手动运行和保存也会使用新脚本，调度定义不因此改变。升级时保留尚未覆盖的旧版最近记录为 `legacy`，无法恢复已被覆盖的历史。

Hermes 只读其 profile 下 `cron/output/<job-id>` 中已有结果文件，沿用 Hermes 自身的保留策略，以保存时间和“已保存”展示，不把文件存在当成执行成功。外部系统任务无可读记录时明确说明。

GUI 和 CLI `automations runs <task-id>`、`automations logs <task-id> --run <run-id>` 共用只读 `history.rs`／`output.rs`。按任务归属和作用域解析记录 ID，拒绝路径穿越和越界符号链接；输出按纯文本展示，最大读取末尾 256 KiB，兼容 PowerShell UTF-16。记录清理、未知状态和读取失败有明确反馈。运行记录位于本机应用运行目录，不进入任务定义的 `pending_backup`，不投影到技能备份元数据。回归测试检查实际 Git remote 只含任务定义，没有 `runs`、日志、退出码或执行内容。

参考 Orca 的变更事件与窗口生命周期：`events.rs` 仅观察注册文件及运行开始／结束标记，合并事件后推送专用通知，GUI 在后台读取；窗口恢复焦点、重新可见和手动操作也会补查。没有定时刷新界面的轮询。日志连续写入、工作目录文件与技能库变动不触发此通知，后台更新保留已显示日志、选中记录、页签和焦点。文件监视失败时仍可手动刷新。这里只刷新展示，不承担调度。

## 验证

单元测试覆盖跨平台配置生成、引号路径、多行脚本退出码、创建者的确切作用域、损坏记录、写锁与失败恢复。`src-tauri/tests/automation_management.rs` 为显式运行的原生验收：生成唯一的用户级手动任务，创建、编辑、拒绝过期版本、手动运行、读取结果、删除并清理；不修改用户已有任务。

```bash
cargo build --manifest-path src-tauri/Cargo.toml --bin agent-hub-cli
cargo test --manifest-path src-tauri/Cargo.toml --test automation_management -- --ignored
```

## Git 自动备份与模板

磁盘清理的可选下载缓存遇到权限拒绝时保留条目，计入跳过与警告并输出路径；只有这些警告时返回 0。其他 I/O 错误、非法规则和工作目录清理错误仍返回非零退出码。该分类不改写已有执行记录，新运行读取修复后的脚本。

任务注册记录同时持久化 `pending_backup`，按任务 ID 合并配置变化与删除标记；只读查询、执行日志与手动触发不进入队列。`backup_workspace::prepare_unlocked` 在既有 RepoLock 内获取自动化锁，将待处理定义投影为技能元数据中的 `.agent-hub/automation-<UUID>.json`，写入后确认队列。此锁顺序固定为 RepoLock → 自动化锁，任务修改本身只持有自动化锁，避免死锁。

这些平铺 JSON 是现有对象合并引擎可识别的 residual blob，按独立任务合并，保留增删与快照恢复；不用会被旧合并引擎忽略的未知子树。投影只包含名称、Provider、命令/提示词、脚本内容、日程和工作目录等定义，不包含调度器标识、配置路径、图标、运行日志、进程和原生包装器。默认工作目录回到未指定语义，主目录内的显式工作目录表示为 `~/...`。

文件监视器额外监视当前应用的注册目录、工作目录及声明脚本的父目录（非递归），检测配置与 Shell／Python 脚本变化；持续使用现有自动备份开关、防抖、重试及错误提示。应用未运行时不新建后台守护进程，下次启动或手动备份处理待提交定义。

Git 内容恢复只更新同步定义，不变更运行中的本机任务。GUI 将备份作为“使用模板”的一类，供查看后新建；CLI 的 `restore` 先预览，`--apply` 显式创建暂停副本。内置模板由 Rust core 生成，GUI 和 Agent CLI 使用同一份当前平台命令；Windows 使用 PowerShell，其他平台使用 `/bin/sh`，Hermes 模板仅安装后返回。

自动备份回归使用本地 bare remote 验证任务定义新增、更新、删除的实际推送，以及快照恢复后定义保留且本机任务不被覆盖。所有数据和目录隔离，未操作用户配置的 Git 远端。

清理模板由 Shell 入口调用预装多文件 Python 包：入口、JSON 配置、安全文件操作、明确目录规则、工具调用、中文总结与通知分开维护，说明文件一并分发。JSON／Markdown 作为任务声明文件与模块一起受路径、64 KiB／32 文件预算、所有权和自动备份约束；配置与脚本修改均触发非递归监视器同步。

默认保留 7 天的下载缓存、Agent 缓存／日志和已退出浏览器缓存；工作目录日志保留 30 天。uv 离线及 Homebrew 官方清理默认启用，保留被引用的依赖、不强制清理。项目目录只从显式配置或当前工作目录获取，不扫描主目录或所有项目；AgentHub 复用已有保留最新构建工具，其他 Rust 项目只清理过期增量缓存，编译期间跳过。普通缓存保留硬链接，显式 Rust 增量目录可以 unlink 过期硬链接，仅移除目录内的名字，其他位置内容保留；共享文件大小与实测磁盘释放量分开展示。链接／junction、越界路径、锁文件和删除前已变化的条目均保留。

更新缓存仅在应用标识一致、包版本不高于已安装版且超过保留期时清理；更新进程、pending、新版本和未知格式保留。对话、数据库、凭据、配置、技能、Downloads、安装运行时和 Playwright 浏览器不自动清理。跨平台通知通过系统工具请求，预览不删除也不通知，通知失败不影响清理退出码。CLI 支持配置、保留期、规则和通知开关；原生工具的结果不冒充已确认的文件删除统计。测试只在隔离目录执行，覆盖多文件安装／回读、配置、路径／链接边界、保留版本、预览、错误隔离和通知参数。

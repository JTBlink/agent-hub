# 自动化公共库

用户业务库存放于 `~/.agent-hub/automations/_shared/<name>/`，独立于产品源码和任务包。每库只有一份当前内容，历史由现有 Git 备份保存。产品提供通用管理、校验、备份和 Python 加载器；库代码由用户维护，不绑定平台或组织。

## 定义与依赖

```json
{
  "schema_version": 1,
  "name": "code-host",
  "version": "1.0.0",
  "files": ["__init__.py", "client.py"]
}
```

`library.json` 是清单入口，名称为小写 ASCII，版本使用 SemVer。只消费声明的 UTF-8 文件，最多64个、内容合计1MiB；禁止越界、链接、私有路径及跨平台重名。未声明内容不进入备份，也不作为安装钩子执行。

任务通过现有 `package_options.dependencies` 声明 `{"kind":"library","name":"code-host"}`，可移植包仍保存为顶层 dependencies。保存、导入和运行准备共用校验，缺失库直接报错；不自动安装网络依赖或启动任务。已有任务不声明公共库时保持原行为。

## 管理与加载

CLI `automations libraries` 提供 list、resolve、import、backups、restore、remove、runtime。更新和删除必须携带内容修订；仍被本机任务或任务备份引用的库不能删除，运行或执行状态无法核验的依赖任务阻止更新。暂停的系统任务仍核对手动执行领取标记。

更新先校验完整候选，再在库操作锁下替换当前目录。持久恢复标记保存于 `_shared/.local/`，中断后恢复原内容或完成已验证的替换；未知文件不被覆盖，库内私有状态保留，不进入备份。不提供多版本目录或运行时别名。

Python 任务通过 `libraries runtime` 取得共享加载器，再调用 `load(name, bridge)`。加载器从 CLI 获取经过校验的源码快照，在内存中处理相对导入；同进程继续使用首次加载内容，后续进程读取当前库。任务不复制实现到 scripts/，库源码也不复制为多版本磁盘缓存。加载器沿既有 `python_support` 发布，不另建运行服务。调用方只保留路径解析和接口适配，业务策略与状态仍归具体任务。

## 备份与恢复

库源文件变化通过现有自动化监视器、防抖和自动备份入口处理。运行、日志、环境、锁、私有状态及未声明文件不导出；导入备份不创建运行目录。应用关闭时沿用现有机制，后续启动或 CLI 备份补处理，不增加后台守护进程。

库的可移植元数据使用 `.agent-hub/automation_library-<name>.json`，Git 仓库发布为 `automations/_shared/<name>/`。本机 `_shared/.local/backup-index.json` 只记录已导出内容指纹，区分本地新增/修改/删除与远端尚未恢复或已更新的备份；本机未变化时不覆盖远端新内容。该索引不是业务执行状态。

Git同步仅发布备份元数据，不热替换本机库或启用任务。`libraries restore` 显式恢复库，覆盖已有库必须提供当前修订。恢复任务时，缺失的声明库先从备份恢复，任务仍按既有规则默认暂停；已有库保留当前内容。导出前检查任务引用的库是否完整，意外删除库不能产生缺依赖的任务备份。

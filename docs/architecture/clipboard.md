# 剪贴板与文件粘贴

`core/clipboard` 是原生文件引用读取和内容分类的公共模块，不依赖终端、文件树或 Tauri 窗口。终端与文件树从该模块读取文件引用，不各自解释剪贴板 URL。

## 读取与分类

1. command 核验调用窗口，在主线程调用 `clipboard::files::request_files`。macOS 读取 `public.file-url`，Linux 异步请求 URI，Windows 读取文件拖放格式；普通文字路径不视为文件引用。
2. macOS 文件引用 URL 可能包含 `/.file/id=…`，这是文件身份，不是磁盘路径。先拒绝非本地文件 URL，再通过 `NSURL.filePathURL` 解析真实路径；文件改名后仍能解析，引用失效时明确报错，不回退到文件图标。
3. 终端在后台线程调用 `clipboard::read_content`，按文件、图片、文字的顺序读取。存在文件时不读取图片或文字备选；没有文件且图片读取失败时读取普通文字。文件树只消费文件引用。

文件读取上限为 4000 项，检测不读取文件内容、不修改系统剪贴板，也不轮询。macOS 回归测试使用独立命名剪贴板。

## 消费边界

- 终端适配层将文件路径转成带引号转义的字面参数，前端通过 xterm 的粘贴入口写入，保留换行规范化和括号粘贴，不自动回车。文件名中的空格、中文、引号和 Shell 符号保留字面含义。
- 图片像素发送 Ctrl+V，由前台程序读取系统剪贴板；普通文字直接粘贴，不将形似文件引用的文字重新解释为文件。
- 快捷键和右键菜单共用原生终端剪贴板入口；响应返回后核验焦点和窗格生命周期，避免写入已失去焦点或已销毁的终端。
- 文件树通过 `project_file_actions::paste::copy_into` 校验目标与源文件，沿用暂存、同名不覆盖及失败恢复约束。

公共模块测试锁定分类优先级；macOS 原生回归覆盖文件引用、改名、失效引用，以及终端路径转义和文件树复制。修改后仍需用新构建的桌面进程验证系统复制到终端的实际结果，旧进程不会因磁盘可执行文件更新而自动加载新代码。

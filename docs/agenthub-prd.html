Product Requirements Document

让 Agent 配置与 Skills，
看得见、改得安全。

AgentHub 是一个本地优先的 AI Agent 工作空间管理器。它把 Claude Code、Codex、OpenCode 的配置和 Skills 汇聚到同一个工作台，但不接管终端，也不在未确认时覆盖任何文件。

V1 · 规划中桌面端 / Tauri 2 + ReactOwner · AgentHub teamLast updated · 2026-08-22

Problem

用户正在失去什么

  • 多个 Agent 的配置分散在隐藏路径，无法快速判断生效层级。
  • Skills 来源、版本和兼容性缺少统一视图，更新容易覆盖外部修改。
  • 配置修改缺乏 Diff、备份和回滚，错误成本高。

Promise

V1 要交付的确定感

  • 一次扫描，知道每个 Agent 的配置健康度。
  • 一次计划，看到目标、文件动作、权限、Diff 和回滚点。
  • 一次确认，安全执行；任何失败都保留旧内容。
北极星指标：用户能在 3 分钟内定位一个配置或 Skill 的“来源 → 生效范围 → 变更风险”，并能在不丢数据的前提下完成一次更新。

Usability corrections

针对当前“看得到，但不容易完成任务”的优化

问题：主页以工程状态和模块卡片为主用户看不到风险优先级，也不知道下一步处理什么。
→
优化：任务导向的工作台首屏只突出待确认计划、诊断和可更新项，每个卡片给一个明确动作。
问题：配置元数据、源码和诊断堆在同一长页内容密度失控，作用域与当前文件上下文容易丢失。
→
优化：列表 → 详情的渐进展开上下文栏固定显示 Agent / scope / workspace，表单、源码和 Diff 用同级视图切换。
问题：写入风险只在动作末端出现外部修改、unknown 兼容性和目标冲突发现过晚。
→
优化：诊断前置 + 统一变更计划列表即显示状态；高风险条目阻止进入批量计划，确认页集中呈现 Diff 和恢复路径。

Information architecture

工作台总览 → 专题页 → 变更计划

三层信息结构兼顾发现、深入和确认。写入动作不藏在列表按钮里，统一进入可审阅的变更计划。

01 / Orient

工作台总览

健康度、待确认计划、Skill 更新和最近活动。用户从这里决定下一步。

02 / Inspect

专题页

配置中心聚焦 Agent/作用域/文件；Skills 中心聚焦来源/兼容性/安装目标。

03 / Commit

变更计划

统一展示 Diff、权限、备份和冲突诊断；确认后才执行原子替换。

Layout rules

导航
≥1024px 固定 240–256px 左侧栏；768–1023px 收为 64px 图标栏 + tooltip；≤767px 使用顶部栏 + 可关闭抽屉。核心导航始终可达。
内容
桌面最大宽度 1,280px；页面内采用 8px spacing rhythm；卡片内边距 20–24px，列表行高 ≥44px。
层级
页面只保留一个主 CTA；次要动作降级为 outline；危险动作与主操作至少间隔 8px，并使用文字说明。
路径
深层页面固定显示 Agent / scope / workspace 面包屑；返回保留筛选、滚动位置和草稿。

Type & motion

字体
标题 JetBrains Mono 600；正文 IBM Plex Sans 400/500；路径、checksum、版本使用等宽字体。
字号
12 / 14 / 16 / 18 / 24 / 32px；正文最小 16px，辅助信息不低于 12px；正文行高 1.5–1.7。
反馈
点击 100ms 内给 pressed/loading；异步超过 1s 显示 skeleton；成功 toast 3–5s，错误保留在问题附近并给恢复动作。
动效
只动 opacity/transform，300–400ms；尊重 reduced-motion。不得用动效隐藏诊断、Diff 或确认按钮。

State model

所有页面都必须实现的状态

Loading保留页面骨架；扫描超过 1s 显示 skeleton 和取消入口。
Empty解释为什么为空，并提供“扫描 Agent / 添加来源”主动作。
Blocked说明阻止原因和下一步；不把按钮做成无响应的 disabled。
Success显示完成对象、时间、备份引用和“查看历史”入口。

Functional requirements

功能需求与边界

需求 ID 可直接映射到 `.scratch/agent-hub-v1/issues/`；实现时按优先级拆分提交。

ID / 优先级 需求 行为与验收口径 不做什么
F-01 · P0 首次扫描 启动后发现 Claude Code、Codex、OpenCode 的全局配置；用户可添加工作空间并重新扫描。扫描结果含实际路径、格式、checksum、parse status 和诊断。 不自动创建配置目录；不执行 Skill 中脚本。
F-02 · P0 配置浏览与编辑 按 Agent / 作用域 / 文件类型筛选；详情支持表单、源码和 Diff。解析失败仍可查看原文，但不可生成结构化写入计划。 不把扩展名以外的格式猜成受支持格式。
F-03 · P0 安全变更计划 每次写入前重新读取并比对 revision，展示文件动作、权限、冲突、备份与回滚点；用户确认后原子替换并重新解析验证。 不在列表内直接覆盖文件；外部修改时阻止静默覆盖。
F-04 · P1 Skill 来源与发现 支持 preset、skills.sh、Marketplace、Git、本地目录；来源与 Descriptor 分离，保留 requested/resolved ref、commit、内容指纹和诊断。 不把同名不同来源 Skill 自动合并。
F-05 · P1 Skill 生命周期 浏览、安装、更新、启用、禁用、卸载均生成 InstallPlan；兼容性为 incompatible 不进默认计划，unknown 必须显式确认风险。 不执行来源仓库中的脚本、hooks 或模板。
F-06 · P1 历史与恢复 记录编辑、回滚、导入和 Skill 操作的状态、时间、checksum 与备份引用；回滚是新操作，不删除历史。 日志和 SQLite 不保存 token、password、完整配置正文。

Non-goals

V1 明确不包含

  • 云同步、账号计费、多人协作
  • 远程 Agent 托管与内置对话终端
  • 完整插件市场和自动化脚本执行

Safety invariants

不可破坏的约束

  • 磁盘文件是唯一真实数据源
  • 所有副作用经 Rust 业务模块
  • 失败时保留旧文件和可恢复备份

Acceptance

验收清单

完成定义同时覆盖业务正确性、风险提示和页面可用性。

核心流程

  • 新用户可以完成首次扫描并看到健康度。
  • 用户能在 Agent/作用域筛选后打开一个配置文件。
  • 表单编辑会生成包含 Diff 和备份的计划。
  • 外部修改、解析失败、缺失和不可读均有可操作诊断。
  • Skill 可从至少一种 Git 来源安装到两个不同目标。
  • 未知兼容性不能进入默认批量计划。

质量与工程

  • 页面在 375 / 768 / 1440 px 宽度无横向滚动。
  • 可见焦点、顺序标题、按钮文本和状态不依赖颜色单独表达。
  • 遵守 `prefers-reduced-motion`，不以动画隐藏关键信息。
  • 运行 `npm run build`、`npm run test`、`npm run lint` 和 Rust 检查。
  • 文档、实现与 `.scratch/` 状态保持同步。

Skill 安装交互流程

v0.1.2 | 2026-09-08 | AgentHub Skills 中心 | Matter 待创建

1 背景

Skill 可来自 Git 仓库、skills.sh、Marketplace 或本地目录。远端安装通常已有官方 CLI 习惯；本地目录则可能一次包含多个 Skill，用户需要先选择目录、批量勾选 Skill，再决定安装到哪些 Agent 和范围。现有安装动作涉及来源解析、兼容性判断和冲突处理，用户容易在“来源是什么、会写到哪里、是否覆盖文件”这些问题上迷失。

2 方案

在 Skills 中心统一提供安装向导，但保留远端和本地两条不同路径：远端 Git 默认沿用 npx skills add <repo-url> --skill <name> 的官方安装意图；本地目录使用 AgentHub 原生扫描和批量选择，不强行转成远端命令。两条路径都先生成不可变安装计划，用户确认后才写入磁盘；所有结果进入变更历史并支持回滚。示例使用 ui-ux-pro-max，不限制其他 Skill。

3 功能点

功能说明
来源类型选择支持 Git URL、skills.sh 仓库、Marketplace manifest、本地目录；切换来源类型时只显示对应字段。
来源与 Skill 发现远端扫描展示来源名称、requested ref、resolved commit；本地扫描展示授权目录、Git commit（如有）或内容指纹、可安装 Skill 列表和入口文件。
Skill 详情与多选本地目录发现多个 Skill 时以列表展示名称、描述、入口和风险提示，支持全选、反选和逐项勾选；脚本只读列出，不执行。
兼容性判断按 Claude Code、Codex、OpenCode 展示 supported / unknown / incompatible 及证据；unknown 需明确确认。
安装范围与目标多选 Agent；安装范围使用“全局 / 工作区”中文文案。工作区范围必须选择具体工作区，并展示最终目标目录。
安装计划展示每个目标的新增、修改、跳过、冲突文件，内容指纹、备份点和回滚前提；外部修改会使计划失效。
执行与结果确认后展示扫描、写入、校验、完成进度；成功、失败、中断三态分别提供查看历史、重试、重新扫描或回滚入口。
交互一致性复用当前桌面端深蓝主区、浅色侧栏、青绿色主操作、卡片和 SVG 图标；步骤、焦点、禁用态和状态提示清晰可读。

4 设计原型

原型入口：打开 Skill 安装交互原型。原型默认展示本地目录路径和多个 Skill 勾选；Git 远端页保留 ui-ux-pro-max 命令示例。

1选择来源2扫描发现3选择 Skill4选择目标5确认计划6安装结果

本地主路径：Skills → 添加 Skill → 本地目录 → 选择目录 → 扫描 → 多选 Skill → 选择 Agent/范围 → 查看计划 → 确认安装 → 查看结果。远端路径：选择 Git/skills.sh/Marketplace → 扫描 → 选择 Skill → 复用后续步骤。

5 技术方案

规则说明
远端命令GitHub 默认保持官方 npx skills add 安装意图；AgentHub 负责展示计划和结果，不改写命令语义。
本地来源npx skills add <local-path> --list 可验证本地目录；AgentHub 先授权目录并扫描，支持一次勾选多个有效 Skill。
结构化输入UI 字段映射到来源对象，不拼接执行任意 shell 字符串。
发现不等于安装扫描只产生 Skill Descriptor；只有确认安装计划后才创建 Installation。
多目标隔离每个 Skill + Agent + 范围 + 工作区单独生成计划项，任一冲突不会静默覆盖。
安全与回滚写入前备份；不执行仓库脚本；失败或中断可从历史恢复。

CLI 事实依据：Source Formats 明确支持本地路径；本地路径必须使用 ./、../ 或绝对路径（Windows 盘符也支持），裸目录名可能被当作 GitHub shorthand。--skill 可筛选多个名称，--global 选择用户级范围，--copy 选择复制而非符号链接。

6 边界条件

  • 远端地址无效 → 对应字段报错，不开始扫描。
  • 本地目录未授权、消失或不可读 → 提示重新选择，不读取目录外内容。
  • 来源可访问但没有有效 SKILL.md → 显示不可安装原因，不生成计划。
  • 发现多个 Skill → 默认不全选，至少勾选一个后才能继续；支持全选/反选。
  • 兼容性 unknown → 展示证据，未确认时禁止继续。
  • 工作区不存在 → 清空失效选择并要求重新选择。
  • 目标同名 Skill 或文件有外部修改 → 标记冲突，要求重新扫描或明确处理，不静默覆盖。
  • 网络、权限或磁盘空间错误 → 保留输入和扫描结果，提供重试；未完成写入不显示成功。

7 验收标准

  1. 四种来源类型均能进入对应表单，切换类型不会保留不适用字段。
  2. GitHub 远端默认展示 npx skills add <repo-url> --skill <name> 意图；输入 ui-ux-pro-max 示例可发现并选择 Skill。
  3. 本地目录可通过目录选择器授权，扫描结果列出全部有效 Skill，并支持至少两个 Skill 同时勾选。
  4. 扫描结果包含来源版本/指纹、入口文件、文件数量和兼容性状态。
  5. 未选 Skill、Agent、工作区或未确认 unknown 时，下一步按钮禁用。
  6. 计划页按每个 Skill × Agent × 范围展示路径、文件动作、冲突、备份和回滚信息，确认前不写盘。
  7. 确认后按阶段显示进度，成功写入每个安装记录并可从变更历史查看。
  8. 失败、中断、外部修改三种异常均有明确文案和可执行的下一步。
  9. 键盘可完成流程，焦点可见；375px 至 1440px 宽度无横向滚动；状态不只依赖颜色。

11 本地 Skill 专项交互

本地来源是重点场景。用户添加一个本地 Skill 仓库根目录后，AgentHub 扫描其中所有 SKILL.md，再以复选框列表呈现多个 Skill。目录选择是单个 Source 根目录，Skill 选择支持多选、全选、反选、搜索和已安装状态筛选。

模式写入关系适用场景安全要求
Link原始目录 ← symlink → Agent开发 Skill，修改后立即生效目标已有真实目录时拒绝覆盖；展示链接目标。
Import原始目录 → AgentHub Library → Agent长期管理与版本固化复制前生成指纹和备份；源目录变化不自动覆盖已导入版本。

12 已安装与多 Agent 管理

Installed 页面统一显示 Skill 名称、描述、Source、版本、安装方式、更新时间、Scope、Project Path 和当前状态。矩阵按 Skill × Agent 展示状态，点击“✓”进入 Manage / Remove，点击“−”进入 Install to。

                     Claude Code   Codex   Cursor
frontend-design          ✓           ✓       −
code-review               ✓           −       ✓
qt-development            ✓           ✓       ✓
testing                   −           ✓       −

卸载必须按实际文件重新检测状态，不能只修改数据库；批量卸载先展示 Skill × Agent × Scope 计划，后台免交互执行后刷新矩阵。

13 底层原则

  • AgentHub 不重新定义 Skill 标准，也不重新实现 Agent Skill 安装体系；优先复用 vercel-labs/skills。
  • AgentHub 负责 GUI、Source 管理、批量操作、Link/Import 参数和跨 Agent 状态管理。
  • Discover 与 Install 分离：获取列表不会写盘；所有写入、更新、卸载都先生成计划并确认。
  • 后台执行不弹出 Terminal；结果写入变更历史，失败保留上下文并提供重试/回滚。

# 帮助文档维护

此目录是桌面帮助和公开文档站的唯一正文来源。导航在 [navigation.yml](navigation.yml)，网站配置在 [文档站配置](../../docs-site/.vitepress/config.mts)。架构、ADR、规划和项目开发规范保留原位，不进入帮助包。

## 新增文章

1. 在 `zh/<分类>/` 新增 `.md`。使用稳定的英文短 id；它决定分享地址，文件所在目录不决定地址。
2. 填写 frontmatter，再写一个与 `title` 一致的 H1 标题。
3. 在导航分类的 `articles` 中加入 id；首页推荐通过 `featured` 配置。
4. 执行 `npm run docs:check`，用 `npm run docs:dev` 预览网站，用 `npm run dev` 预览桌面界面。
5. 检查正文和章节链接、图片、版本说明，再提交内容源、导航及相关变更记录。

```yaml
---
id: example-guide
title: 示例操作指南
description: 一句话描述文章帮助用户完成的任务。
since: "0.1.4"
tags: [项目, 团队]
related: [project-team-sharing]
---
```

必填字段为 `id`、`title`、`description` 和 `since`。`since` 是功能开始适用的应用版本，不是文章创建日期；版本高于根目录 `VERSION` 的文章不发布。`tags`、`related`、`aliases`、`reviewed` 和 `draft` 可选。推荐文章应记录 `reviewed: "YYYY-MM-DD"`，只记录实际核验日期。

## 草稿与版本

`draft: true` 的文章不进入离线内容或网站页面。草稿和尚未支持的版本不得放入正式导航，也不能从已发布文章链接过去；构建会拒绝这些引用。

离线帮助随应用构建并显示 `VERSION`，网站也显示其构建版本。现有 Pages 仅在版本 tag 或手动运行时发布；修改 Markdown 不会自动部署。文档纠错可以手动部署对应代码，但要确认说明仍适用于标注版本。当前没有历史版本选择或文档热更新。

## 链接与图片

文章间使用相对 Markdown 链接，例如 `[团队共享](../guides/project-team-sharing.md)`。构建将其转换为稳定文章路由；移动文件时更新内容源的相对引用，分享地址不变。

章节使用标题生成的锚点，例如 `#交付给团队`；同名章节依次添加 `-1`、`-2`。标题锚点采用 GitHub slug 规则，在网站和应用一致。改章节标题可能使旧章节分享链接失效，尽量保持已有标题。

图片统一放在 `assets/`，通过相对路径引用；构建只复制已发布文章实际引用的图片到应用与网站，离线可读。共享正文支持标准 Markdown/GFM，不允许 HTML、Vue 组件、自定义容器、脚本协议、外部图片或内容目录中的符号链接。外部链接使用 HTTPS。

## 翻译与旧地址

在 `en/` 或 `zh-TW/` 添加相同 `id` 的文章，每个译文可以独立维护标题、摘要和正文。缺少译文时逐篇回退简体中文，并明确显示提示；网站三种语言入口均可阅读。

正常维护应保留 id。确需改变 id 时，在元数据中使用 `aliases: [old-id]`，并更新导航与相关引用。应用识别别名，网站为旧地址生成链接页。别名不能与其他文章或别名冲突；同一文章的别名统一用于所有语言入口，新增译文不会删除旧分享地址。

带章节的内部跳转保留源链接的目标语言，避免中文章节误跳到英文译文；应用路由用经过校验的 `lang` 参数保留正文语言，分享地址同样对应实际阅读的正文。

## 自动检查与生成物

- `npm run docs:check`：校验元数据、导航、身份、内部链接、锚点和图片，不写生成物。
- `npm run docs:generate`：校验后生成两端文档内容。
- `npm run docs:build`：生成公开文档站到 `_site/docs/`。
- `npm run website:build`：合并产品首页和文档站到 `_site/`。

应用开发、测试和生产构建自动准备文档；直接启动 Vite 时也会在解析应用模块前生成离线文档。开发服务器监听内容变更并重新生成；如果调整网站导航或分类配置，请重启网站开发服务器，使站点配置重新读取导航。

`src/generated/help/`、`public/help-assets/` 和 `docs-site/.generated/` 是可重建目录，不提交、不手动编辑。新增文章不需要修改 React 页面；新增分类只需配置其三语标题和成员。

## 官网更新日志

官网主导航与页脚提供帮助、更新日志入口。更新日志网页位于 `docs/zh/changelog.html`，构建时直接读取根目录 `CHANGELOG.md`，保留版本章节并说明 `Unreleased` 是尚未发布的开发变更；英文与繁体界面明确提示正文回退简体中文。日志不进入桌面离线帮助文章目录，无需在帮助导航 YAML 中重复维护。

修改更新日志后执行 `npm run website:build` 并按既有 Pages 流程部署；文档开发服务器会监听日志变化并刷新生成页。官网顶部与首屏下载按钮直接进入 GitHub Releases。

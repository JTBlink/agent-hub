# Skill 使用技巧

先选当前任务需要的 Skill，再告诉 Agent 目标、范围和验收方式。刚开始可以从测试、调试、审查三个方向入手，具体集合见 [Coding Skills 推荐集合](coding-skills.md)。

## 从导入到使用

1. 在 AgentHub 中从来源仓库或本地目录导入 Skills，打开详情阅读 `SKILL.md`，确认名称、依赖和操作流程。具体步骤见[管理技能库](../guides/skill-library.md)。
2. 将经常一起使用的 Skills 加入“Coding 基础”等[技能组](../guides/skill-groups.md)。
3. 在目标全局或项目工作空间批量添加该组，确认目标 Agent 能读到技能。特定团队的规范优先通过[项目技能库](../guides/project-team-sharing.md)共享。
4. 在 Agent 的对话中调用 Skill，并补充任务上下文。AgentHub 负责管理和部署，实际执行由目标 Agent 完成。

技能组是集合，**不会自动按顺序执行工作流**。修改成员后，还需要检查并更新对应工作空间的部署。

## 调用时说清四件事

| 信息 | 示例                                                 |
| ---- | ---------------------------------------------------- |
| 目标 | 给项目列表增加名称搜索                               |
| 范围 | 修改项目列表，沿用现有数据读取方式                   |
| 输入 | 现有需求文档、相关模块、错误日志或审查基准           |
| 验收 | 搜索大小写不敏感，清空恢复全部项目，无结果时显示提示 |

下面的提示词可直接修改后使用：

```text
使用 tdd Skill，为项目列表增加名称搜索。
先阅读项目规范与现有列表实现，沿用当前数据读取方式。
先确认要测试的公开行为，再逐项写失败测试和最小实现。
验收：大小写不敏感、清空恢复全部项目、无结果有提示。
完成后运行相关检查，并说明结果。
```

## Skill 名称与调用语法

不同 Agent 的显式调用方式不同。支持斜杠命令的宿主可以尝试 `/tdd`；支持技能选择或 `$` 引用的宿主按其界面选择。自然语言也可以明确写“使用 tdd Skill”，并确认 Agent 确实读取了入口文档。

下文推荐文章中的 `/skill-name` 是调用示例，**以目标 Agent 支持的方式为准**。如果名称找不到，先检查部署位置和 `SKILL.md` 的 `name`，再核对是否为不同版本。

## 每个阶段选择一个主流程

- 需求还不清楚：先澄清目标、例外和不做的范围，再形成规格。
- 已有明确规格：进入实现流程，需要测试时使用 `tdd`。
- 出现错误或性能退化：使用 `diagnosing-bugs`，提供复现步骤、预期与实际结果。
- 实现完成：使用 `code-review`，提供比较基准与需求文档。

主流程可以使用测试、领域建模等辅助 Skills。避免同时给 Agent 多套不同的任务分解、提交和发布流程；项目已有约定时，在任务开头指明应沿用哪套规则。

## 团队使用的小习惯

让项目规范记录目录入口、术语、验证命令和任务记录位置，通用 coding 技巧与团队约定分别维护。开新对话时附上规格路径、已完成任务和剩余问题，帮助 Agent 接续工作。

社区 Skill 的操作可能包含写任务、修改领域文档、建立分支或提交。首次使用前阅读实际入口，并在提示词中说明本次需要完成到哪个阶段。每次更新后检查差异，再决定是否同步团队版本。

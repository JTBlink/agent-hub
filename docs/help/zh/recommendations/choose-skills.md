# 如何选择 Skill

Skill 推荐应从真实任务出发。相同名称不代表相同内容，安装前应阅读入口文档、附带脚本和运行条件。

## 选择标准

- 能清楚说明适用场景和完成结果。
- 内容职责单一，能与其他技能组合。
- 来源、许可和更新方式可核验。
- 所需凭据、网络和本地操作与你的使用环境相符。

## 团队技能

团队的提交规范、架构说明和项目引导通常值得形成自己的 Skill。通过项目技能库随 Git 管理，让评审和回滚覆盖内容变更。

## 社区来源

查看来源仓库的入口文档、维护记录和许可后再决定是否导入。推荐文章的核验日期只代表最后一次检查，不保证外部仓库永久保持原状。

开发任务可从 [Coding Skills 推荐集合](coding-skills.md)开始，了解 matt 系列的测试、调试、审查与需求流程。如何部署和调用见 [Skill 使用技巧](skill-usage-tips.md)，其他组合见[按任务搭配 Skills](workflow-recipes.md)。

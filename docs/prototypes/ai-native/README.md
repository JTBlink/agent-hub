# AI Native 独立需求原型

单文件交互原型：[index.html](index.html)。直接双击打开，无依赖；也可使用项目入口：

```sh
./prototype.sh ai-native
./prototype.sh ai-native --layout B
```

首次进入实验性功能页面。按 `⌘ K`（Windows/Linux 为 `Ctrl K`），输入 `agent-hub://flags` 也可打开该页面。AI Native 默认关闭，手动开启后显示独立侧栏入口，无需重启原型。这里只演示应用内地址解析，未注册系统协议。

场景包括需求与开发、缺陷修复、Issue 处理、MR 处理、发布检查、L3 建设与验收、自定义。需求与开发是一条流程。默认使用 ask-matt 编排，下游 Skill 和脚本可替换；不在普通页面堆叠框架字段。

人确认需求和测试 Case，AI 在已授权范围内自动完成中间阶段，最后由人验收。参考 setup-ai-native 的前置验收、三层验证、失败修复、当前版本 Review / CI、证据和门禁约束。L3 基线单独保留 60 个必要子项，全部待验；演示通过不代表真实验收。

可编辑节点名称、类型、目标、依赖、执行条件与顺序。流程 JSON 支持导入、导出、结构校验和环检测；脚本以 argv 数组声明。编排入口和修复预算可定制。外部脚本可以生成同一 JSON；实际调度器、执行适配器与断点恢复尚未实现。

三种布局通过底部切换器或 `?variant=A|B|C` 比较：A 流程编排（推荐）、B 执行记录优先、C 交付验收优先。主题可切换，字号可放大。各布局共用场景配置。

建议体验路径：开启功能 → 需求与开发 → 选择节点并编辑 → 流程文件中校验/导出 → 发起任务 → 编辑并勾选 Case → 预览自动推进 → 查看执行记录 → 演示阻塞与恢复 → 最终验收。也可在流程中加入人工节点，观察演示停止位置。

所有数据只在内存中，刷新恢复默认关闭。执行日志和证据均为合成展示，不调用 Skill、脚本、IPC、网络或真实仓库。没有创建工作项、提交、MR、合入、发布或远端配置变更。设计方案内置在“设计说明”并可导出 Markdown。

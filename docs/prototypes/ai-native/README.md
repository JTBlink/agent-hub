# AI Native 独立需求原型

单文件交互原型：[index.html](index.html)。直接双击打开，无依赖；也可使用项目入口：

```sh
./prototype.sh ai-native
```

从原型目录的“打开原型”或上述启动命令进入时，使用 `?view=sidebar` 直接显示 AI Native 侧栏与主面板，模拟已开启状态，便于查看设计。

目录中的“开关页面”及不带 `view=sidebar` 的单文件入口进入实验性功能页面。按 `⌘ K`（Windows/Linux 为 `Ctrl K`），输入 `agent-hub://flags` 也可打开该页面。AI Native 默认关闭，手动开启后显示独立侧栏入口，无需重启原型。这里只演示应用内地址解析，未注册系统协议。

场景包括需求与开发、缺陷修复、Issue 处理、MR 处理、发布检查、L3 建设与验收、自定义。需求与开发是一条流程。默认使用 ask-matt 编排，下游 Skill 和脚本可替换；不在普通页面堆叠框架字段。

人与 AI 可以多轮沟通需求，AI 将需求落实为一个可交互的 HTML 原型，用户预览确认后开始执行，最后验收结果；需求、验收标准、测试 Case 与实施计划由命令行 Agent 在编码前生成和保存，再连续完成开发、验证、失败修复与评审，不设置独立的人工 Case 确认步骤。参考 setup-ai-native 的前置验收、三层验证、失败修复、当前版本 Review / CI、证据和门禁约束。L3 基线单独保留 60 个必要子项，全部待验；演示通过不代表真实验收。

可编辑节点名称、类型、目标、依赖、执行条件与顺序。流程 JSON 支持导入、导出、结构校验和环检测；脚本以 argv 数组声明。编排入口和修复预算可定制。外部脚本可以生成同一 JSON；实际调度器、执行适配器与断点恢复尚未实现。

默认进入三步：**沟通并确认 HTML 原型 → AI 自动推进 → 验收结果**。需求页支持多轮对话、HTML 原型生成/更新、预览与下载，“确认此原型，开始执行”是唯一的执行边界；未发送的补充必须先处理，Case 不需要逐项人工确认；场景及启动设置可选，验收页突出交付结果、验证情况和待解决问题，Case 与证据按需展开。复杂节点、Skill、脚本与 JSON 设置放在“高级编排”。

侧栏以独立需求为单位管理多条任务。“新建需求”不会中断其他任务的演示推进；需求、Case、流程定义、运行进度与验收结果分别保存。演示推进使用任务 ID 定位，后台任务结束只更新自身状态，不覆盖当前任务的表单。刷新后清空。

只保留一套交互方案，不提供 A/B/C 切换。右下角“原型选项”仅提供主题、字号、设计说明与重置。

建议体验路径：描述目标 → 多轮补充与调整 → 生成并预览 HTML 原型 → 反复修改 → 确认原型 → 在推进中再建一条需求 → 切换查看各任务 → 验收结果。需要定制时进入“高级编排”，编辑节点或流程 JSON 后返回引导。

所有数据只在内存中，刷新后清空演示配置。普通入口恢复默认关闭；侧栏预览链接恢复模拟已开启状态，不改变正式产品默认关闭的设计。执行日志和证据均为合成展示，不调用 Skill、脚本、IPC、网络或真实仓库。没有创建工作项、提交、MR、合入、发布或远端配置变更。设计方案内置在“设计说明”并可导出 Markdown。

需求输入框下方可下拉选择项目默认 Agent、Codex、Claude Code、OpenCode 或 Hermes；选择按任务独立保留，切换场景时沿用，并反映在演示提示词与启动记录中。选项为合成数据，不代表本机安装状态。任务默认优先通过 Herdr 承载所选 Agent CLI；未安装 Herdr 时降级到 AgentHub 内嵌终端（PTY），不打开系统终端。可手动选择内嵌终端，启动选项内提供模拟 Herdr 未安装的演示入口。已经启动或结果不明的任务不会因切换承载方式而重复发起。“查看终端任务”只展示提示词与演示输出，未实际调用进程。AI 在需求对话中逐步整理范围和验收标准；用户确认当前 HTML 原型后才自动生成 Case 并推进，执行中超出授权或环境受阻时保留现场。每条任务独立保存对话、草稿、HTML 版本历史和确认快照。

需求最终交付单个可下载的 `.html` 文件，摘要仅作辅助。原型预览使用无同源权限的 sandbox iframe；当前文件是确定性的交互示例，未调用模型按任意目标生成真实产品界面。沟通追加后，旧原型标为待更新；必须重新生成、预览并确认当前版本，执行上下文绑定其文件名、版本和内容。不同修订保留历史，但每次只评审一个方案。

需求落在目标项目固定目录 `docs/prototypes/requirements/`，每条需求一个稳定文件，例如 `REQ-0001.html`；修改沿用文件名，修订号单独记录。目录提供 `index.html` 与 `catalog.json`，新需求按创建顺序置顶，修改旧需求不重新排序。侧栏“项目需求目录”可查看并导出索引，HTML 文件也可单独下载；将索引与需求文件放在同一目录时使用相对链接打开。原型编号仅为演示，正式实现须从项目索引分配稳定且唯一的编号，并在写入冲突保护下原子更新需求与目录，不覆盖已有需求。索引状态是展示投影，工作项仍为任务状态真源。执行记录及本机状态不进入需求目录。

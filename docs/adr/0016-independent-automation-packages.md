# ADR-0016：独立自动化任务包与安装生命周期

- 状态：已接受
- 日期：2026-10-30
- 执行记录：[独立自动化任务包](https://github.com/JTBlink/agent-hub/issues/222)

## 背景

原有任务的默认脚本目录已经独立，但完整定义、清理重试和备份状态依赖全局 `tasks.json`，模板安装动作也没有统一回执。需要将任务作为可安装、卸载、导入和导出的独立内容单位，同时保留现有调度器和旧用户数据。

## 决策

新任务以独立包为权威来源，使用稳定 UUID 和按名称安全分配的目录。`task.json` 只保存清单、相对入口及文件列表；正文保存在 `scripts/`、根目录提示词和说明文件。本机工作目录放在 `.local/binding.json`，调度标识、安装阶段、错误和备份待处理状态放在 `.local/receipt.json`；执行记录、私有环境和更新恢复 journal 同样留在 `.local/`。

只在已知托管根目录扫描一层包，不依赖全局文件恢复新包的唯一内容。逐包报告损坏和身份冲突。兼容期原有任务继续从原格式读取，不在启动或列表查询时自动搬迁。显式迁移保留原 ID 和日程，先准备副本并暂停调度，再切换入口及旧记录；失败恢复原配置并保留重试信息，原项目目录不被搬走。

GUI、CLI、模板与导入共用 core 生命周期。安装先准备私有依赖、持久注册目标并注册暂停任务，提交回执后才启用日程。卸载先阻止新执行，再撤销调度并清理有归属证据的依赖或权限资源，保留正文及历史。删除默认保留包文件并取消管理；只有明确选择清理本地数据才删除包，项目和其他任务引用的资源受到保护。

同任务使用稳定进程锁，不同任务不共用长操作锁。锁文件保存在系统应用数据目录的 `operations/<uuid>/`，使删除包期间及进程重启后的锁身份一致；这是相对初稿把锁放进包内的调整。全局兼容记录与备份提交只持有短锁。原生运行入口在 `.local/` 中通过安装标记和运行领取保护执行与卸载的竞争。

Python 依赖按声明的确定版本进入任务自己的环境，更新候选使用新的环境目录；外部命令只探测，不卸载用户已有工具。普通导入脚本不作为安装钩子执行。内置网络重置使用嵌入的专用安装动作，系统管理员授权后创建按任务 UUID 命名的权限入口，按回执卸载；旧的无回执权限入口继续保留外部归属。

导入支持可移植 JSON、包目录和目录内清单文件，先校验并预览，再从预览的正文创建新 ID 的未安装任务。GUI 直接提交预览对象，避免预览后源文件变化；导出只包含声明的正文和依赖意图。本机路径、回执、凭据引用和运行证据不进入包；正文中的用户自定义文本保持原样。备份恢复同样默认未安装。

系统计划继续使用当前用户的 launchd、systemd timer 或 Windows 任务计划程序。Hermes 原生任务仍通过 CLI 管理，无法消除其集中保存 `jobs.json` 的外部限制；所需脚本通过该 profile 的独立桥接入口调用任务包，确切路径和归属保存于回执，不通过软链接逃逸脚本目录约束。

## 影响与验证

任务目录隔离不构成操作系统沙箱。已安装外部 Agent、模型配置、凭据和项目不会随任务卸载。新建和安装不执行正文；系统日程在启用后按正常匹配时间运行，手动执行保留原语义。跨文件和调度器的操作使用持久阶段与恢复信息，不承诺分布式原子提交。

验收覆盖包损坏隔离、锁范围、导入导出及依赖保留、运行门控、安装失败与重复卸载、更新中断恢复、迁移身份保留和回滚。管理员动作仅在专门授权的原生验收中执行，日常测试只检查生成脚本；平台单元测试不能替代对应系统的原生验收。

### 分发与云端目录统一

仓库根目录 `automations/` 与 `skills/` 并列，保存可实际安装的任务包；应用编译嵌入同一来源，独立的 `catalog.json` 仅补充推荐展示与平台适配信息。云端备份同样发布 `automations/<任务名>--<稳定标识>/task.json` 与正文文件，名称变化不改变包内身份，同名任务不会互相覆盖。旧 `.agent-hub/automation-*.json` 保持读取兼容，下次备份迁移至目录结构。本机仍使用独立包和私有 `.local/`，云端恢复仅保存定义。

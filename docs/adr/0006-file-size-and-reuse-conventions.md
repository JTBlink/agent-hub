# ADR-0006：文件体量、模块拆分与代码复用规范

- 状态：已接受
- 日期：2026-08-23

## 背景

桌面端页面、Tauri command 和 Skill 扫描逻辑会同时增长。若把展示、状态、文件系统和领域规则继续堆在单个文件中，修改一个功能会牵连整页回归，重复实现也会造成 Agent 目录规则不一致。

## 决策

### 文件体量上限

- React/TypeScript 页面文件建议不超过 400 行；超过 600 行必须拆分，超过 800 行禁止继续新增功能。
- Rust 领域模块建议不超过 500 行；超过 800 行必须按职责拆分。
- 单个函数建议不超过 50 行；超过 80 行需要说明为什么不能拆分。
- 单个组件只负责布局与组合；数据读取、转换、交互流程和领域判断分别下沉到 hook、`src/lib` 或 Rust module。

这些是拆分触发线，不要求一次性重写历史代码。新增或修改功能时，优先把触碰到的职责迁移到新模块。

### SOLID 落地规则

- **单一职责**：扫描、诊断呈现、安装计划、文件迁移不能互相持有实现细节。
- **开放/封闭**：新增 Agent、Skill 来源或安装策略时扩展 enum/adapter，不在全局 `if/else` 链中复制规则。
- **里氏替换**：所有 `AgentConfigAdapter`、`SkillSourceAdapter` 实现必须遵守同一错误、只读扫描和授权边界。
- **接口隔离**：command 只依赖所需的 repository trait；不要为一个页面注入“万能 service”。
- **依赖倒置**：领域规则依赖 trait 和值对象，UI 通过 `src/lib` bindings 调用 command，不直接拼接路径或执行文件系统操作。

### 复用优先级

1. 先复用领域类型、path resolver、扫描器和现有 command。
2. 再抽取纯函数或小组件；重复出现两次先记录，第三次必须抽取。
3. 只有语义和生命周期都不同，或抽取会引入更高耦合时，才允许局部实现，并在代码注释中说明边界。
4. 禁止复制 Agent 路径、作用域标签、诊断文案和安装安全校验；统一从单一来源生成。

### UI 文件拆分建议

页面壳保留路由、页面级状态和组合；列表行、详情面板、空状态、弹窗和来源向导各自独立。共享显示规则放在 `src/lib/*-presentation.ts`，共享调用放在 `src/lib/backend.ts`。

## 验证要求

- 拆分或复用后必须保留原有行为测试，并为新增边界添加回归测试。
- Rust 运行 `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings` 和相关集成测试。
- 前端运行 `npm run build`、`npm run lint` 和 `npm run test -- --run`。
- `git diff --check` 不得有空白错误。

## 影响

规范允许渐进式治理，不要求为了满足行数一次性大规模重构；但新的安装、诊断和 Agent 兼容逻辑必须落在可复用边界内。

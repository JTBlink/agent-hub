# ADR-0021：独立窗口复用完整工作区

- 状态：已接受
- 日期：2026-11-10

## 背景

任务源码弹窗只读取任务定义中的文件快照，无法展示完整目录及运行记录，也没有项目工作区的编辑、搜索、Git 和终端能力。用户要求通过独立窗口打开目录，并完整复用现有工作区。

## 决策

继续使用唯一的 React + Tauri 应用入口。后端创建新的本地应用窗口，直接进入既有项目工作区路由；不增加另一套源码浏览器、侧栏或编辑器。窗口原生配置继承当前产品的主窗口配置，标题栏、主题和缩放沿用公共组件。

任务源码入口优先打开 `script_dir`，旧任务回退到 `workdir`，读取真实文件系统，包含 `.local/` 和 `config/task.json`。复用 Herdr 的元数据登记流程到通用模块，只登记项目，不初始化技能目录。已有项目及已知 Git worktree 保持原身份；规范目录对应稳定窗口标识，重复打开时聚焦已有窗口。

只有主应用 WebView 和后端登记的工作区 WebView 可以调用应用命令。新增窗口加载相同本地前端并限制顶层导航来源；预览子 WebView 不进入登记表，不获得应用权限。权限配置中的工作区标签模式仅提供原生插件能力，内置 IPC 仍校验实际登记身份。

终端与预览标签布局按窗口独立保存，主窗口沿用旧存储键。终端 PTY、待启动资源和每窗口八窗格限额按所有者隔离。关闭附加窗口只回收自己的资源；有其他工作区时关闭主窗口会隐藏主窗口，保留托盘恢复入口。退出应用时先由各窗口处理未保存文件，任一窗口取消则保留所有窗口。全体同意后再执行统一退出清理。

## 影响

文件菜单新增“新建工作区窗口”；任务源码变为可编辑的真实工作区。预览、任务编辑中的文件快照仍由原阅读组件承担。ADR-0008 的单一应用源码与数据模型继续适用，此处的多窗口不是旧版双宿主集成。

跨窗口编辑同一文件继续使用现有保存前内容比对，避免静默覆盖其他窗口的修改；干净文档在窗口恢复焦点时刷新。

工作区切换器与原生菜单共用最近项目选择规则：按 `visited_at` 降序，最多 15 条。旧版本无打开时间的条目暂以 `updated_at` 排序；超出上限时将 `visited_at` 置为 `0`，只移除最近历史资格，保留项目注册、技能关联与窗口状态。重新打开恢复时间并自动清理最旧条目，已打开窗口通过 `project-visits-changed` 同步打开时间（不重新扫描项目技能）；当前窗口选中的项目即使被其他窗口挤出历史，仍保留可用的选择项，总数不超过 15。

打开文件夹通过 `resolve_workspace_project` 复用真实目录登记，不在打开链路中扫描所有项目的技能。新增项目直接并入当前窗口状态，其他窗口用轻量项目元数据补齐；访问时间更新只同步历史。原生菜单的显式事件 ID 包含所属窗口 label，防止全局 Tauri 菜单通道互相覆盖；同一窗口重建菜单复用这些 ID。
